## 主线

2026 年 10 月 20 日，DeepSeek 开源了支撑自家线上服务的推理框架 DeepInfer，同时开源了配套的生产级 Token 编解码组件 deepseek-recipe。开源本身不是新闻——真正的新闻是官方在同一天第一次披露了**线上真实运营数据**：单一集群每天服务 155 万亿 Token，整体收入是每卡每小时 38 美金（按谷价）。

在此之前，整个 AI 产业的成本讨论都停留在报价单层面：每百万 Token 多少钱。这是第一次，有厂商把「一张卡每小时到底产出多少收入」这种只能靠内部账本才能算出来的数字摆到了公开场域。这组数字把行业的竞争标尺从「谁的分数高」推到了「同一项任务谁更便宜」。

值得写的判断有三层：成本优势的真实来源（不是 GPU 便宜，是缓存命中率高）、开源的边界（最难的那块恰好没开源）、以及 Agent 时代推理成本结构的变化（存储和调度的权重第一次超过了算子优化）。

## DeepInfer 是什么

一句话：**DeepSeek 自家线上服务用的推理引擎**，支撑 DeepSeek-V4.1-Flash 的高吞吐低延迟服务。

基本盘：

- **许可证**：Apache 2.0。模型权重另为 MIT（HF `deepseek-ai/DeepSeek-V4.1-Flash-1017`，763B 参数）
- **支持模型**：只有 DeepSeek-V4.1-Flash 一个
- **支持硬件**：NVIDIA SM100（Blackwell）、华为昇腾 950 NPU
- **构建要求**：Linux、GCC ≥ 13.0、Python 3.12、CUDA 13 或 CANN 9.2
- **血统**：主要基于 vLLM 构建，吸收了 SGLang 和 TensorRT-LLM 的思路
- **上游组件**：FlashMLA、DeepGEMM、DeepEP、TileKernels、DeepSelect、自研 TileLang kernel

架构上是 **Vision Encoder / Prefill / Decode 三段分离部署**：

- Prefill：EP2~8 / DP2~8，显存够就用最小的 EP/DP
- Decode：EP64~128（Wide-EP），显卡够就用最大的 EP/DP
- Vision Encoder：一般单卡即可，建议用最便宜的卡
- ATTN 部分沿用 V3/R1 的做法，DP 数等于 EP 数

最小可部署单元是 1P + 1D，但由于推荐 Decode 用 EP64 以上，**真正高效的生产单元是 64 张 Prefill 卡 + 64 张 Decode 卡**。这个门槛本身就说明：DeepInfer 不是给个人开发者用的玩具。

## 三个值得写进文章的工程机制

### 1. SWA Bounded Replay：把「重算成本」从变量变成常数

V4 的做法是把 SWA KVCache 落盘，未命中时精确重算（层数 × 窗口）个 token 逐层恢复窗口状态。代价是 SWA KVCache 吃掉了持久化缓存近一半容量，却带不来对应的命中收益——Block KVCache 是数天长尾复用，SWA KVCache 只在活跃会话内分钟级复用。

V4.1 改成 **SWA KVCache 完全不落盘**，只重算最近 128 个 token，并把注意力窗口截断在重算段内：从位置 s 起回放，位置 i 的 query 只和 max(s, i−127) 到 i 区间的 key 计算。重算代价由此变成与上下文长度和层数**无关的常数**。

收益是 Decoder 侧总 prefill 计算量近乎减半（精确重建需要 20 个 decoder 层跑最后 2560 个 token，改为只重算末尾 128 个 token）。

技术报告原本提的 Zero SWA Caching（完全不落盘、只靠精确重算）因为代价过高，在 V4.1 生产系统里没被采用。**这是全文最有价值的一个工程判断**：技术报告里的最优解和工程落地的最优解经常不是同一个。

配套数据：SWA KVCache 线上 TTL 约 180 秒，命中率 98% 以上；存储在产出它的 prefill/decode 机器内存里，不进 3FS，跨机命中靠 400G VLAN 拉取。

### 2. KVCache Storage：3FS 从训练基础设施变成推理基础设施

Block KVCache 落在独立的 3FS 分布式文件系统的存储集群上，不放本机内存：

- 容量约 **100 PiB SSD**
- 峰值聚合读带宽 **10 TiB/s**，写带宽约 **850 GiB/s**
- 纠删码 **10+2**，每个 EC 组容忍 2 节点同时故障；读取时同时向组内 11 台存储节点发请求，任意 10 个响应即可解码返回
- block 粒度约 112 KiB
- TTL：agent 流量 3 天，chatbot 流量 7 天。3 天左右的 TTL 会造成 chatbot 流量命中率下降 0.5%–1%
- 每 GPU 约 14.4 TB 逻辑容量；存储服务器配置建议 20 × 30.73 TB SSD，单台至少 40 GB/s 读、5 GB/s 写

为什么用独立存储集群而不是多级存储：独立集群让**任意一台 prefill 机器都能命中任意前缀**，从而避开「前缀亲和路由」和「负载均衡路由」之间的冲突，同时把存储和计算的扩缩容解耦，且计算节点故障不会带走缓存（计算节点故障率比存储高一个数量级以上）。

命中路径分三段，只有第一段在关键路径上：**匹配**（Entrypoint 在本机 CHECK 角色的 kvcache-store 上做哈希链前缀匹配，只查元数据，但命中长度要在路由前算出来，无法掩盖）→ **取 KV**（独立进程异步从 3FS 搬进宿主机 shm）→ **换入**（引擎进程内线程做 shm→HBM 逐层传输，与前向计算重叠；因为 CUDA copy engine 对细粒度 KV block 拷贝性能差，换入用 GDR 实现，RDMA 网卡打满 PCIe 带宽且不占 SM）。

### 3. DSpark：变长验证的投机解码

DSpark 用 Confidence Head 预测每个 draft token 的接受率，调度时把验证算力分配给边际收益最高的 token。线上 draft 一次生成 5 个 token，按预期接受率排序后选有效吞吐最大的前缀子集验证。

效果（英文 Q&A 给出完整表格）：相比固定验证 5 个 token，变长验证每步少验证约 30% 的 draft token（5.00 → 3.2–4.4），平均接受长度基本不变（3.29 vs 3.20）。吞吐增益随并发变化：16 seqs/rank 时 **−1.5%（负收益）**，32 时 +1.6%，60 时 +5.4%，96 时 +11.0%。官方知乎专栏的说法是「线上部署场景吞吐提升 6%」。

这组数据的价值在于它揭示了投机解码的真实条件：**收益区间很窄，而且低并发下是负的**。对比 DFlash 的做法——在 base logits 上叠加只依赖前一 token id 的低秩 logit bias，用极轻量的串行修正补回相邻 token 的局部条件化信息。

### 附：Wide-EP 与异步调度

Wide-EP 的收益是大幅降低 MoE 专家部分的每步显存流量，配合 EPLB 有效提升 TPS。官方 EP8 vs EP64 对比图显示 EP64 在所有 batch size 下都领先。

Asynchronous Scheduling（Zero-Overhead Batch Scheduler）解决的是 Decode 步骤里的 GPU 空转：`schedule(N) → forward(N) → sample(N) → post-process(N)` 中，schedule 和 post-process 是纯 CPU 逻辑，post-process(N) 之前需要 GPU-CPU 同步。异步化后 GPU 执行 forward(N)→sample(N) 时，CPU 并发执行 schedule(N+1)→launch_forward(N+1)→post-process(N−1)→launch_sample(N+1)，GPU 全程无空闲。参考实现是 SGLang 和 NanoFlow。

EPLB 策略：Prefill 每卡 4 个冗余专家起步、统计窗 100 步、每 1000 步重排；Decode 每卡 1 个起步（EP64 取整后每卡共 7 个专家，不含共享专家）、统计窗 1000 步、每 10000 步重排。

## 低精度计算

这次开源里有一个容易被忽略但影响深远的部分——FP4 已经下沉到 KV 和 MoE 权重：

- Main KV：per-16，e4m3（类似 NVFP4，但不带全局 scale）
- Indexer KV：per-32，ue8m0，MXFP4
- MoE routed-expert 权重：per-32，ue8m0，MXFP4

这解释了为什么单 token 的 KV 大小能一路压下来。知乎社区分析引用的技术报告数据是：从初代模型到现在，单 token 的 KV 大小降了 437 倍。

## 开源了什么，没开源什么

**开源了**：优化算子（FlashMLA、DeepGEMM、DeepEP、TileKernels、DeepSelect、自研 TileLang kernel）、模型与采样运行时、Attention DP / balanced CP、MoE EP + EPLB、DSpark 置信度调度验证、SWA bounded replay、异步调度、batch-invariant inference（仅 NVIDIA）、确定性采样（仅 NVIDIA）、结构化输出（JSON schema / 正则 / EBNF）。

**本版本不含**（官方明确列出）：

1. KV cache 系统
2. VE/Prefill/Decode 分离部署
3. 跨 DP 副本的负载均衡（prefill 与 decode 两端）

官方给的理由是这些组件与内部基础设施耦合过深，代码尚未完整开源，设计细节只写在长文和问答里。

**这个取舍本身就是选题**。按前面的架构分析，把离线批处理变成线上服务的那一层（KV cache 管理 + PD 分离 + 负载均衡）恰好是撑起 155 万亿吞吐的核心。其他厂商拿到 DeepInfer 能在 decode 效率上学到很多，但要复现这个吞吐，还得自己搭一套百 PiB 级、带宽 10 TiB/s 量级的存储，再把缓存策略调到能稳定拿到九成以上命中率。

官方还留了一句承诺：**未来 DeepSeek 新模型的推理代码及后续性能优化也将在 DeepInfer 中持续开源**。默认权重就是 V4.1 Flash-1017，模型与框架互为入口。

另外，同期开源的 deepseek-recipe 是个容易被低估的组件。它是 Rust 实现 + Python 绑定，处理逻辑与 DeepSeek 官方 API 完整对齐，第三方部署能获得与官方部署一致的 API 体验。它的核心能力是防 special token 注入：用户在输入、工具返回或工具调用参数里写 `<｜User｜>` `<｜image｜>`，会被编码成普通 token 序列，不会触发控制 token 影响模型行为。输出侧则按 token ID 识别思考结束标记 `</think>` 和 DSML 标签中的 `｜DSML｜`。

## 38 美元该怎么读

这是全篇最需要小心的一节。**155 万亿和 38 美元两个数字的限定词，在二次传播中几乎全部丢失。**

**官方口径**（DeepSeek 知乎专栏 + GitHub `doc/inference_deployment_qa.md`，两处一致）：

- 155 万亿 Token/天 = **单一集群**当前的服务吞吐，不是公司整体，更不是全行业。换算约等于每秒 17.9 亿 Token
- 38 美金/卡/小时 = **收入**，不是利润，且特意限定**按谷价计算**——是下限不是均值

**谷价/峰价的具体定义**（DeepSeek 官方定价页，美元计价，每百万 Token）：

| 项目 | 谷价 (OFF-PEAK) | 高峰价 (PEAK) |
|------|-----------------|-----------------|
| 输入（缓存命中） | $0.003 | $0.006 |
| 输入（缓存未命中） | $0.15 | $0.3 |
| 输出 | $0.6 | $1.2 |

高峰时段为 UTC 01:00–04:00 与 06:00–10:00，周一至周五（不含中国法定节假日），即北京时间 09:00–12:00 与 14:00–18:00，一周 35 小时，约占全周 21%。**其余时间一律谷价**，含周末和中国全部法定节假日。并发上限 2500。

**自己算一遍 38 美元的含义**（基于官方吞吐 + 官方定价页，可复现）：

设集群卡数为 N，则日收入 = 38 × 24 × N = 912N 美元；日处理 1.55×10¹⁴ Token = 1.55×10⁸ 百万 Token。

- 全部按最便宜的缓存命中价计：1.55×10⁸ × $0.003 = $465,000/天 → N ≈ **510 卡**
- 全部按缓存未命中输入价计：1.55×10⁸ × $0.15 = $23,250,000/天 → N ≈ **25,500 卡**

也就是说，**集群规模被夹在约 510 到 25,500 张卡之间**，真实值取决于缓存命中/未命中/输出三类 Token 的比例。官方没有公布卡数，这个区间就是当前信息下的全部范围。

**缓存是这组数字的真正杠杆**。36氪报道的线上统计：约 96% 的输入直接命中缓存不用重算；同一张卡跑 Prefill，不算缓存命中每秒处理 6 万 Token，算上命中能到 150 万，**差 25 倍**。38 美元省下的不是电费，是重复计算。

同一批线上统计（36氪口径）：平均每个请求输入 77K Token，首字时延平均 400 毫秒，生成阶段每秒输出 230 个 Token，写代码时能到 300 个。

**还有一层容易被忽略：38 美元不是 GPU 的价格**。它是「GPU + 100 PiB SSD + 3FS 文件系统 + 400G 网络 + Agent 场景的高复用流量」这一整套的定价。把卡单独拿出来换一家没有这套存储、没有这种流量结构的公司来跑，跑不出同样的效果。

## 与 2025 年的对照

知乎社区的一手对比分析（第三方引述，非官方）：

| 指标 | 2025 开源周 | 2026-10 |
|------|-------------|---------|
| 单集群日吞吐 | 不到 1 万亿 Token | 155 万亿 Token |
| 缓存命中率 | 56.3% | 估算 90% 以上 |
| 每卡每小时收入 | 约 $12.9 | $38 |
| 日输入 / 日输出 | 6080 亿 / 1680 亿 Token | — |

**吞吐涨了约 200 倍，收入只涨了约 3 倍**。中间那道差就是缓存命中：这类 Token 价格极低，计算量也极低——它抬高吞吐，但对收入贡献不大。

用户结构也变了。2025 年初以 chat 为主，一问一答、前缀重复不多。现在 Agent 场景占了大头：一个编程 Agent 每走一步，都要把系统提示词、工具定义、前面几十轮的上下文和读过的文件重新发一遍，上下文几十万 Token，新增内容可能只有几百个。这种流量天然高命中。

## 性能数据

**离线 benchmark 条件**（官方）：Prefill 用 4 张 SM100，Decode 用 64 张，各在一个 scale-up 域内。上下文长度 131,072。

- **Decode**（EP64/DP64，nextn=3，接受率 75%）：256 requests per rank 时超过 25,000 tokens/s/GPU，单用户接近 100 tokens/s；8 requests 时单用户速度超过 300 tokens/s
- **Prefill**（EP4/DP4，140 token bounded replay）：4,096 tokens per rank 时约 60,000 非缓存 tokens/s/GPU；65,536 tokens 时吞吐接近 90,000，每步约 730 ms
- **负载均衡效果**：达到完美均衡离线 benchmark 的约 80%

**开源版与内部版差距**：内部 FlashMLA 解码 kernel 比开源版快 5%–10%（缺一个手工 SASS 优化），端到端差距在 5% 以内。DeepGEMM / FlashMLA 的内部版「大体相同」，indexer 和 mega 系列有差异。

## 关键矛盾

1. **开源的边界由什么决定**。DeepInfer 开源了算子和引擎，没开源 KV Cache 管理和负载均衡。开源策略是按「与内部基础设施的耦合度」划线，而不是按「对社区最有价值的部分」划线——这与外界期待的「最有价值的先开源」逻辑相反，值得追问
2. **38 美元是收入不是利润**。扣掉 GPU 折旧/租赁、100 PiB SSD、3FS 集群、网络、运维人力之后还剩多少，官方没给。而 GPU 租赁市场价（第三方引述：NVIDIA B300 平均 $7–10/小时，最低 4.89，AWS 最高 17.8）与 38 美元的对比，很容易被读成「囤卡套利」，这是误读
3. **谷价口径是保守还是刻意**。按一周 35 小时的高峰时段（21%）和两倍峰谷价差、流量均匀分布粗估，实际收入应该比 38 美元高两成左右。选谷价作为披露口径，是留了余量
4. **吞吐竞赛的意义在衰减**。155 万亿 Token 说明的是规模，而规模本身对普通用户没有价值；有价值的是同样规模下的价格。行业该开始拆开报命中/未命中/输出三类 Token，因为它们的计算成本能差两个数量级——一个以 Agent 为主、命中率 90%+ 的平台，和一个以聊天为主、命中率 50% 的平台，同样的总 Token 数对应完全不同的算力消耗
5. **对比标尺正在切换**。DeepSWE v1.1 官方对比里，V4.1 Flash-1017 以 77.0% 通过率拿下第一，单任务平均费用不到 2 元；通过率相近的 Opus 5 和 GPT-5.6 Sol 单任务费用要三四十元，差二十多倍。MiniMax M3.1 Flash 跑完 ALE 全部 152 个真实任务总成本约 739 元，GPT-5.6 Sol 约 5000 元、Claude Opus 5.5 近 9000 元，通过率却在同一档。**按任务算账正在取代按千 Token 算账**

## 值得深挖的数据点

**官方口径（一手）**

## 创作方向建议

### 方向 A：推理经济学第一手账本（推荐）

以 38 美元/卡时为锚点，拆解「一张卡一小时能产出多少收入」这个从未被公开过的指标：口径还原（收入非利润、谷价非均值、单集群非全公司）→ 缓存的 25 倍杠杆 → 155 万亿与 38 美元之间那道 200 倍对 3 倍的差 → 为什么 38 美元不是 GPU 的价格而是整套系统的价格。落点在「行业该开始按任务算账，而不是按千 Token 报价」。

素材密度最高，且自带一个反直觉的判断：**吞吐涨 200 倍而收入只涨 3 倍，恰恰说明规模不是护城河，缓存命中率才是**。

### 方向 B：缓存即利润，存储成为推理基础设施的新主角

从 V4 → V4.1 的 SWA 存废决策切入，讲一个「用 SSD 和文件系统换算力」的故事：V4 把 SWA 落盘吃掉一半持久化容量却没换来命中收益 → V4.1 改成完全不落盘 + 128 token bounded replay → 持久化 KV 缩到 V4 的八分之一 → 3FS 从训练侧基础设施变成推理侧基础设施（100 PiB / 10 TiB/s）→ SSD 厂商和分布式存储团队在推理链条里的权重上升。

技术判断密度高，适合走 deep-tech 深读路线。风险是需要较多篇幅解释 CED 架构和 SWA 窗口。

### 方向 C：开源的最难部分

以「DeepInfer 开源了什么、没开源什么」为切口，分析开源策略的边界到底由什么划：官方给的理由是耦合度，但社区拿到的是没有 KV Cache 管理和负载均衡的离线推理框架，恰好缺了把离线批处理变成线上服务的那一层。对比 vLLM / SGLang / TensorRT-LLM 的开源模型覆盖（200+ 架构 vs 1 个）和在线服务能力（都有 OpenAI 兼容 server，DeepInfer 没有）。

落点在「开源这个动作本身已成为模型的竞争维度，但它同时是一种选择性披露」。

### 方向 D（不推荐单独立篇，适合做 A 的收尾）：价格战已经开始

DeepSeek 10-17 更新模型价格未动 → MiniMax 10-19 砍到约一半 → DeepSeek 10-20 开源摊开成本曲线。三天三步，顺序很清晰：对手先降价，自己后亮底牌。这条线本身信息量足够，但单独成篇容易和已有的《AI 价格战》《Token Jevons 悖论》《AI 模型价格战生态战》重复，建议作为方向 A 的最后一节处理。

→ **「降价 4–10 倍」对应的 N 区间约 6,000–15,400 卡**

**推导 C｜卡数反推（输出占比是杠杆）**
```
输入平均单价 = 0.96×0.003 + 0.04×0.15 = $0.00888/M（96% 命中，36 氪口径）
混合单价 = 0.00888×(1−x) + 0.6×x          （x = 输出 Token 占比）
N(x) = 1.55×10⁸ × [0.00888(1−x) + 0.6x] ÷ 912 = 169,956 × [0.00888 + 0.59112x]
```
**输出占比每升 1 个百分点 → 反推卡数增加约 1,005 张。**

交叉锚点：**3FS 约 100 PiB ÷ 官方「每 GPU 约 14.4 TB」→ N ≈ 7,300–7,800 张**（TB / TiB 两种口径同量级）→ 代入解得 **x ≈ 6%**。

**推导 D｜为什么 510 卡下界不成立**
- 155×10¹² ÷ 86400 = **1.794×10⁹ tokens/s**（全集群）
- 510 卡 → 每卡需 **3.518×10⁶ tokens/s**
- 实测上限：Prefill 计入缓存命中 **1.5×10⁶ tokens/s/卡**（36 氪）；Decode **25,000 tokens/s/卡**（官方 benchmark）
- **3.518×10⁶ > 1.5×10⁶ → 物理上不可能**
- 更严谨：即便把全部 token 当缓存命中输入（N = 1,509），也要求纯输入零输出，对真实服务不成立

**推导 E｜正文落点**
> **「38 美元」本质上是关于输出 Token 占比的函数，而不是关于缓存命中率的函数。**
> - 输出价 $0.6/M（谷）是缓存命中输入价 $0.003/M 的 **200 倍**
> - 命中率 56.3% → 96%：把纯输入混合单价从 $0.0158/M 压到 $0.00888/M（1.8×）
> - 输出占比 0 → 10%：把混合单价从 $0.00888/M 拉到 $0.068/M（**7.7×**）
> - 同一个「38 美元」，能对应一张 1 万卡的集群，也能对应一张 5 万卡的集群——差在输出占比，不在命中率

**写法约定**：不写成「我们算出了集群有 7,800 张卡」，而写成「**官方刻意没给的数，是可以从官方自己给的两个数推出来的**」。卡数只作推演中间量，结论落在推导 E。**SSD 账单缺口（100 PiB SSD 采购成本）要在正文主动点破**——「这张账单还没公开」本身就是结论的一部分。
