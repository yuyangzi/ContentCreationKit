# QCon 上海 2026：企业 Agent 从"能跑"到"可托付"

## 类型标签

`#企业AI` `#Agent落地` `#QCon` `#AgenticInfra` `#上下文工程` `#生产可靠性` `#多Agent`

## 主线

2026 年 10 月 22–24 日，InfoQ 中国主办的 QCon 全球软件开发大会上海站举行，1,200 余位从业者到场，70 家企业与机构的 140 位讲者同台。主会场六场演讲主题各异，指向同一个变化：企业对 AI 的关注，正在从"模型能做什么"转向"系统能否稳定完成任务"。"能跑"不再是卖点，"可托付"才是——任务是否完成、结果能否验证、过程能否追踪、失败后能否恢复，成为新的评价坐标。

## 核心信号

### 1. 评价体系换锚：从模型能力到任务闭环

极客邦科技总编赵钰莹在《从 Agent 到自主智能》中判断：随着基础模型能力提升，行业关注点已从模型本身扩展到 Agent 工程、多智能体协作、上下文管理、评测体系和生产可靠性。她的两句话构成全场基调：

- "模型能力并不是决定 Agent 落地效果的唯一因素，工程框架同样会直接影响任务完成质量"
- "AI 转型真正深刻的变化，不只是效率提升，而是岗位分工、业务流程和组织结构的重新设计"

### 2. 多 Agent 反噬论：越多不一定越好

赵钰莹明确警告：过多的 Agent 可能带来更高的通信成本、错误传播风险和协作损耗。企业真正需要关注的是四件事——任务是否完成、结果能否验证、过程能否追踪、失败后能否恢复。这与业界"编排层级越堆越多"的惯性形成张力。

### 3. 上下文工程是"零和一"

阿里巴巴千问办公副总裁任卿把企业级 AI 与通用对话产品的差别归结为上下文工程："对企业级 AI 来说，上下文工程带来的差别不是一百倍，而是零和一，是可用与不可用的区别。"上下文不只是一段提示词，还包括用户身份、权限范围、历史行为、业务对象及其关系。与之配套的是 Agent 的"刹车能力"：关键操作前确认权限、敏感动作留痕、异常时停止/回滚/转交人工——企业级 Agent 不仅要有加速能力，还要有刹车能力。

### 4. Agentic Infra 的双向命题

上海交大副教授、无问芯穹联合创始人戴国浩提出 Agentic Infra 包含两个方向："不仅是 Infra for Agent，还有 Agent for Infra"——基础设施要支撑 Agent 的运行与进化，Agent 也参与算子优化、系统运维、资源调度。配套的计量转向：过去看单卡吞吐、Token 价格、响应延迟，未来要看"完成一个可验证任务，需要多少综合成本"——真实任务不是一次模型调用，而是包含规划、执行的完整链路。

### 5. 确定性分工：AI 生成程序，程序执行逻辑

涛思数据 CEO 陶建辉在工业场景给出一条分工原则："可以用 AI 生成确定性的程序，但没有必要让 AI 每次都重新执行确定性的逻辑。"规则明确、结果稳定、高频执行的任务，让 AI 生成经过验证的程序再持续运行；AI 留给开放问题、复杂意图和动态决策。这与 Breunig "确定性代码吃掉概率性调用"的判断（见同日 topic：从 Context Engineering 到 Harness Engineering）在不同场景下同频出现。

## 关键矛盾

1. **演示与生产的落差**：从"模型能做什么"到"系统能否稳定完成任务"，说明大量企业已经过了尝鲜期，卡在生产可靠性
2. **多 Agent 的规模不经济**：通信成本与错误传播让"堆 Agent"的路线开始反噬，与编排层级军备竞赛形成对照
3. **加速与刹车的平衡**：Agent 越接近真实业务，判断错误的影响越大——刹车能力（权限、留痕、回滚）成为企业级的准入门槛而非加分项
4. **计量口径迁移**：单次调用价格战的指标体系，正在被"每个可验证任务的综合成本"替代

## 创作方向建议

1. **"可托付"四件套**（推荐）：以完成、可验证、可追踪、可恢复为骨架，整合 QCon 信号写企业 Agent 评价体系的换锚——接续《AI-Agent落地大考》与《Agent生产化鸿沟》的既有线索
2. **多 Agent 反噬**：通信成本 + 错误传播 + 协作损耗，与已发的复合意图四级编排文章对照——什么时候该停在单 Agent
3. **刹车能力清单**：权限确认、动作留痕、异常回滚/转人工，企业级 Agent 的准入设计，可与 Human-in-the-Loop、权限边界三范式串成系列
