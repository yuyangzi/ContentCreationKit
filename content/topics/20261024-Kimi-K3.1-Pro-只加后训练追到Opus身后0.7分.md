# Kimi K3.1 Pro：只加后训练，3T 开源模型追到 Opus 身后 0.7 分

## 类型标签

`#后训练` `#强化学习` `#开源权重` `#Agent能力` `#模型安全` `#Kimi` `#Moonshot`

## 主线

2026 年 10 月 23 日，月之暗面发布 Kimi K3.1 Pro。它不是新一代基座，而是 K3 的后训练版本：基座不动，后训练算力大幅增加，强化学习从少数领域扩到数百个下游领域。结果是 Terminal-Bench 4.0 拿到 65.7%，距 Claude Opus 5.5 的 66.4% 只差 0.7 分，比 GPT-6 Astra 的 58.2% 高 7.5 分。完整权重承诺 11 月 4 日前开放。

**日期口径**：官方博客的资源路径、知乎问题创建时间都指向 10-23；36氪稿件标注 10-24。正文统一用 10-23，引用 36氪时保留其原始标注。

这次发布有两个值得写的点。第一，后训练被当成一条独立的 scaling 轴来用：不换基座，只堆后训练算力和环境质量，就能把开源模型推到闭源前沿的射程内。第二，Kimi 主动削弱了模型的网安能力。同一套训练管线不做数据清理能到 90.5% pass@3，发布版压到 81.0%，理由是「不释放会拓展网安能力绝对前沿的开放权重」。

## 后训练到底加了什么

官方说法是把 RL 扩到数百个下游领域，做大规模联合训练。为了让每一份新增 RL 算力都转化成稳定回报，Kimi 改造了整条栈：

- RL 框架
- 长上下文推理
- 训练效率
- 沙箱基础设施
- rollout 调度
- 环境质量检查的共享平台

这段清单比 benchmark 更值得写。它说明「只加后训练」不是省钱的捷径，而是把成本从预训练转移到了环境构建、rollout 调度和质量控制上。数百个领域意味着数百套任务环境，每一套都要能稳定复现、能自动判定、能防止 reward hacking。后训练的 scaling 曲线，本质上是一条基础设施曲线。

内部金融评测的对照更能说明后训练增益的方向：金融建模 57.6 对 K3 的 50.4（+7.2），金融研究 70.4 对 58.8（+11.6），商业运营 37 对 8.9（约 4.2 倍）。

事实准确性上，Kimi Hallu Bench Hard 的 claim-level 幻觉率从 K3 的 23.4% 降到 8.3%。官方特别注明这是压力测试集，不代表日常使用的整体错误率。

**benchmark 口径要注意**：Terminal-Bench 4.0 用的是 Claude-Code harness；官方博客脚注说明，除 DeepSeek 取自发布博客外，其余分数取各博客或官方榜的最大值。跨模型比较时这个 harness 差异必须标注。

## 主动削减网安能力

这是全篇最值得深挖的一段。

Kimi 在开发中发现，随着后训练规模扩大，模型的漏洞研究能力同步上升。追查来源后，他们把原因定位到两处：通用 mid-training 语料里嵌着网安内容，RL 环境组合里也有网安任务。这是「在 broad data 上训练的天然副产品」。

对照实验给出了一个明确的控制杆。内部模型在完全不清理数据的情况下，xdev-bench-hard 的 pass@3 是 90.5%；发布版 K3.1 Pro 是 81.0%。清理动作同时发生在 mid-training 和 RL 两个阶段，但保留通用编程任务。

xdev-bench-hard 是一套内部基准：题目取自 Linux kernel、Node.js、JavaScriptCore、Exim、VirGL 等软件近期披露的漏洞，开启缓解措施，给漏洞源码、简短提示和二进制，要求 Agent 写出 exploit、在独立沙箱里实现任意代码执行、取回 secret string。按 pass@3 计分，不设硬超时和输出 Token 上限。

同一张榜单上的其他数字：

- GPT-5.6 Sol：解出 100 题（第三方评测）
- 未做网安风险削减的 Kimi 检查点：90.5
- DeepSeek-V4.1-Flash：85.7
- K3.1 Pro：81.0
- GLM-5.3：57.1
- K3：33.3

Kimi 给出的开放权重原则有两条：不释放会拓展网安能力绝对前沿的权重；逐步提高开放权重可用的网安能力，让防御方也能用。第二条的论据是，能力开源、跑在用户自己的基础设施上，更多团队才能审计自己维护的代码，包括那些长期没人做安全评审的遗留系统。

这个取舍本身比「90.5 降到 81.0」更有讨论价值：一个开源模型把「能力克制」写进了发布说明，而且给出了可复现的对照实验。

## 长程 Agent 的一个证据

官方给了一个 167 项任务、420 次独立评审的长程案例：基于 human-atlas（296 个骨骼组件、402 个肌肉组件的开源人体解剖模型）搭建行走动力学仿真。

过程里有两点值得记：

- 模型从「走几步就摔」迭代到「交替迈步连续行走 11.2 秒」
- 当调整奖励函数无法改善手臂运动时，它没有继续调参，而是转向检查仿真器动力学，最终发现并修正肩部肌肉力臂计算中的 36 处错误，再重新训练控制器

第二点是长程 Agent 能力的真正证据：它把「优化目标」和「目标所依赖的世界模型」区分开了。多数 Agent 卡在前者，少数能怀疑后者。

## 关键矛盾

1. **「只加后训练」是相对基座而言，不是低成本**。数百个领域的联合 RL 需要沙箱、rollout 调度、环境质检平台，成本结构从「买卡训练」变成「建环境 + 跑 rollout」。这条账官方没摊开
2. **benchmark 的 harness 差异**。Terminal-Bench 用 Claude-Code harness，且分数取各来源最大值。65.7 与 66.4 的 0.7 分差距，落在这个口径噪声范围内，不能写成「追平」
3. **主动降能力既是安全姿态，也是竞争策略**。81.0 仍远高于 K3 的 33.3，但低于 DeepSeek-V4.1-Flash 的 85.7。Kimi 选择不越过网安能力前沿，把更高的能力留给后续版本和闭源厂商，也可能减少监管关注
4. **开放权重与合规**。11 月 4 日前发布是官方承诺，但博客没有提及出口/备案手续。这一点不能推测，写作时只能陈述官方承诺
5. **额度争议与模型能力是两件事**。「10 分钟烧光」是订阅计量问题，不是推理效率结论。两者混在一起会让技术判断失焦

## 创作方向建议

### 方向 A：后训练作为独立 scaling 轴（推荐）

从「基座不动，只堆后训练」切入，拆三件事：数百领域联合 RL 需要什么样的环境基础设施；为什么环境质量检查平台会成为后训练栈的一等公民；当后训练能补上 0.7 分，预训练的边际收益还剩多少。

落点可以是：**预训练决定能力上限，后训练决定能力能不能被调用**。这个判断能用 K3.1 Pro 的金融、3D、长程 Agent 三组数据分别支撑。

### 方向 B：能力克制写进发布说明

以 90.5 → 81.0 的对照实验为核心，讲开源权重时代的安全边界由谁划：厂商主动清理训练数据，和监管强制阉割，是两种不同的治理路径。Kimi 的两条原则（不拓展绝对前沿、逐步提高开放能力）值得逐条拆。

风险是容易写成政策评论。技术支撑要落在「清理发生在 mid-training 和 RL 两个阶段」以及「保留通用编程任务」这两个具体动作上。

### 方向 C：长程 Agent 的证据链

用 human-atlas 案例讲「Agent 什么时候该怀疑目标，什么时候该怀疑世界模型」。167 项任务、420 次评审、36 处力臂错误，是很好的叙事材料。适合走 Agent 工程线，但需要补一点动力学和 RL 背景。

### 方向 D（不推荐单独立篇）：额度与订阅计量

「10 分钟烧光」有传播度，但证据来自社区个案，无法核实。可以作为方向 A 或 B 的收尾注脚，不适合做主线。
