# GPT 和 BERT 的分野，藏在一张下三角矩阵里

> **导读**：GPT 和 BERT 常被当成两种模型，实际上它们共用同一个注意力公式，差异全部落在一张掩码矩阵上：BERT 全开，每个词看完整句；GPT 下三角，每个词只能向左看。这篇文章讲透这张矩阵的数学原理、两条路线的后果，以及 2026 年掩码如何重新变成开放问题。

一个刚接触大模型的人常有的误解是：训练 GPT 时模型看不到后面的词，因为训练的时候后面的词还没生成出来。

这个说法对了一半。它描述的是推理，不是训练。训练时，整句话从一开始就完整躺在显存里，第 100 个词的字面值就摆在模型眼前。真正拦住模型不让它偷看的，不是"看不到"，而是一张锁死了注意力的矩阵。

另一个同样流行的说法是，BERT 不能生成文本。这句话也错了，BERT 不是能力上"不能"，而是训练目标从头到尾没教过它生成。

两个说法都指向同一个东西：一张几乎没人注意的掩码矩阵。GPT 和 BERT 的主要分野，都从这里开始。

## 注意力公式里，藏着第三个参数

Transformer 的核心是 scaled dot-product attention（缩放点积注意力），2017 年那篇《Attention Is All You Need》（arXiv:1706.03762）给出的公式：

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V
```

Q、K、V 三个矩阵分别叫 Query（查询）、Key（键）、Value（值），d_k 是它们的向量维度。每个词发出一个查询，和所有词的键算点积得到相似度分数，除以 √d_k 做缩放（因为 d_k 变大后点积方差跟着变大，softmax 会掉进梯度极小的区域，论文脚注 1 给了这个推导），再过 softmax 变成权重，最后对 V 加权求和。

注意这个公式，只有三个参数。

但论文在 3.2.3 节写了一句几乎所有转述都会漏掉的话：

> We implement this inside of scaled dot-product attention by masking out (setting to −∞) all values in the input of the softmax which correspond to illegal connections.

非法连接，在 softmax 的输入端被设为负无穷。也就是说，实际运行的公式长这样：

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k + M) · V
```

M 就是掩码矩阵（mask matrix）。它不改变 Q、K、V，只往注意力分数上加偏置。合法位置加 0，什么都不变；非法位置加负无穷，该位置的注意力权重被直接归零。

**这张 M 的形状，是 Encoder-only 和 Decoder-only 最根本的分岔点。**

加负无穷而不是加 0，原因在于 softmax 的指数归一化：e⁰ 等于 1。如果把非法位置设成 0，它不但拿到非零权重，还会进分母稀释其他位置的权重，等于没挡住。只有 e 的负无穷次方严格等于 0，权重才能彻底归零。HuggingFace 维护者 Rocketknight1 在 transformers 仓库 Issue #542 里解释过：掩码必须加在 softmax 之前，加 0 挡不住，所以只能加一个大负数。

工程上连负无穷都很少用。Google 原始 BERT 代码与 HuggingFace 早期实现用的是 -10000，因为 fp16 半精度下负无穷会引发数值问题。代码注释里写着：想保留的位置加 0.0，想屏蔽的位置加 -10000.0，效果等同移除。当前 HuggingFace 的实现已改用 `torch.finfo(dtype).min`。

用 PyTorch 把这个逻辑写出来，以序列长度 4 为例：

```Python
import torch

def causal_mask(seq_len):
    # 下三角矩阵：[i][j] = 1 表示位置 i 可以看位置 j
    lower_tri = torch.tril(torch.ones(seq_len, seq_len))
    # 偏置矩阵：能看的位置 +0，不能看的位置 +(-inf)，加在 softmax 之前
    bias = torch.zeros_like(lower_tri)
    return bias.masked_fill(lower_tri == 0, float("-inf"))

scores = q @ k.transpose(-2, -1) / (head_dim ** 0.5)  # QKᵀ / √d
scores = scores + causal_mask(4)                      # 掩码不是乘，是加
weights = torch.softmax(scores, dim=-1)               # 非法位置权重 = 0
output = weights @ v
```

这个函数生成的偏置矩阵长这样，0 代表能看，负无穷代表被锁死：

```
      词1   词2   词3   词4
词1 [  0    -∞    -∞    -∞  ]    词1 只能看自己
词2 [  0     0    -∞    -∞  ]    词2 能看词1和词2
词3 [  0     0     0    -∞  ]    词3 能看词1到词3
词4 [  0     0     0     0  ]    词4 能看到全部
```

对角线以上是清一色的负无穷，形状是一个下三角。这就是 causal mask（因果掩码），"因果"的含义是：后面的词不能影响前面的词。

而 BERT 用的掩码矩阵，是一张全 0 的矩阵。没有任何位置被锁，每个词都能看完整句。

同一个公式，一张全开，一张下三角。两条路线就此分叉。

## 全开的路：双向掩码如何造就 BERT

Encoder-only 的"双向"不是形容词，是数学事实。Transformer 论文 3.2.3 节的原话：编码器里每个位置可以 attend 到上一层所有位置。第 i 个词同时吸收左边和右边的上下文，所以叫 bidirectional（双向）。

BERT 把这件事做成了招牌。论文（arXiv:1810.04805）摘要里那句定义值得整句引用：

> BERT is designed to pre-train deep bidirectional representations from unlabeled text by jointly conditioning on both left and right context in all layers.

所有层、同时、左右上下文。这套设计的直接产物，是 BERT 变成了一台理解机器。它读完整句再下判断，做分类、做问答、做句子相似度时，比只能向左看的模型拥有先天的信息优势。

双向模型有个必须解决的陷阱：一个语言模型要预测某个词，最该屏蔽的信息恰恰是这个词自己。每个词的表示都融入了整句，包括它自己，直接做"预测下一个词"这种语言建模任务会退化成抄答案。BERT 论文 3.1 节解释过：深度双向模型没法像普通语言模型那样训练，词会通过循环间接"看到自己"。

BERT 的解法是 MLM（Masked Language Model，掩码语言模型）：预训练时随机把 15% 的输入词替换成 [MASK] 符号，让模型根据剩下的 85% 补全。其中 80% 的位置是真换成 [MASK]，10% 换成随机词，10% 保持原词不变，这个 80/10/10 分解是为了缓解预训练和微调之间的不匹配，因为微调时输入里没有 [MASK] 这个符号。这里第一次出现了两个不同的"mask"：MLM 的 [MASK] 是替换输入词的符号，而这一节的掩码矩阵是锁注意力的偏置。

双向的红利有多大，BERT 论文用一组消融实验给了量化答案。把 BERT 改成从左到右的单向模型（同时去掉 NSP，模拟 GPT 的结构），MRPC 准确率从 86.7 掉到 77.5，掉了 9.2 分；SQuAD 问答 F1 从 88.5 掉到 77.8，掉了 10.7 分。作者的解释很直白：问答任务里词级别的隐状态拿不到右侧上下文，答案自然抓不准。

代价同样写在这套设计里。MLM 一次前向算完整句，但只在 15% 的位置算 loss，剩下 85% 的 token 不产生自己的预测信号。对比 GPT 的自回归训练，每个位置都在预测下一个词，token 利用率是 100%。EACL 2023 的一篇论文（Wettig 等人）专门检验了"15% 是不是最优"，结论是 BERT-large 规模下把掩码率提到 40% 反而在 GLUE 和 SQuAD 的大部分任务上更好（个别任务如 SST-2 仍是 15% 更好）。信号密度这个短板，是 MLM 路线的结构性成本。

## 锁死的路：因果掩码如何造就 GPT

Decoder-only 那侧的逻辑更简洁：预测第 i 个词，只能用第 i 个词之前的信息。Transformer 论文 3.1 节的说法是，防止位置 attend 到后续位置，配合输出右移一位，保证位置 i 的预测只依赖小于 i 的已知输出。

GPT-1 的训练目标把这条约束写成了条件概率。OpenAI 那份技术报告没有 arXiv 编号，公式是：

```
L₁(U) = Σᵢ log P(uᵢ | uᵢ₋ₖ, ..., uᵢ₋₁; Θ)
```

第 i 个词的概率，条件部分只有它前面的 k 个词。右边的东西在这个公式里根本不存在。GPT-1 的模型规格描述里也直接写了 "12-layer decoder-only transformer with masked self-attention heads"。

有个细节常被中文教程带偏。GPT 不是"Transformer 的 Decoder"。原版 Decoder 里有两层注意力：一层 masked self-attention 负责序列内部，一层 cross-attention（交叉注意力）负责查 encoder 的输出。GPT 没有 encoder 可查，所以那层 cross-attention 整个被删掉了。准确的说法是 decoder-only（仅解码器），只保留带因果掩码的自注意力加上前馈网络。

因果掩码带来一个双向路线没有的礼物：可以生成。预测下一个词这件事天然可递归，生成第 5 个词之后，把第 5 个词拼进输入，再预测第 6 个，一路滚下去。BERT 的完形填空没有这个递推结构，它补完的句子是"算"出来的，不是"长"出来的。

训练效率上也占优。teacher forcing（教师强制）策略下，训练时直接把整句右移一位喂进去，配合因果掩码，所有位置的预测一次前向全部算完，每个位置都产生梯度信号。Transformer 相对 RNN 的最大卖点，训练并行化，就建立在这张下三角矩阵上：虽然每个位置能看的东西不一样，但所有位置可以同时算。

## 同一张掩码，训练与推理的两副面孔

因果掩码在训练和推理里的角色截然不同，这是新手最容易卡住的地方。

训练时，整句都在显存里，模型在物理上"看得到"所有词。掩码是唯一的防线：它把注意力分数锁死，让第 i 个位置的表示在数学上不可能包含第 i 个之后的信息。不是信息没进显存，是信息进不了表示。

推理时，故事反了过来。生成第 5 个词的那一刻，第 6 个词还不存在，未来没有任何东西可泄露，因果掩码在逻辑上自然退场。AI StackExchange 上有个浏览四千多次的问题就是问这个：GPT-2 推理时一次只生成一个 token，掩码还有意义吗？在逐 token 生成加 KV cache 的实现里，每个新 token 的 query 只和历史缓存的 K、V 计算注意力，右边确实什么都没有，掩码就不需要再显式出场。

KV cache（键值缓存）是这段故事的关键工程零件。自回归推理里，生成第 n 个词时，前 n-1 个词的 K、V 已经算过一遍，缓存起来直接复用，每步只算新 token 的那一行。这是因果掩码带来的隐性福利：过去的词只能被未来的词看见，它自己的表示不会因后续生成而改变，所以缓存一次，永久有效。

训练时这套缓存必须关掉。缓存出来的 K、V 是 detached 张量，梯度流被切断，反向传播会静默失效。所以同一个模型，训练和推理是两个显存叙事。

反过来看双向路线就明白代价了。双向注意力里，任何位置的表示都依赖整句。句子里多一个词，前面所有词的 K、V 全部要重算。这是 BERT 系模型没法做高效增量生成的深层原因，它不只生成能力没被训练，连工程上复用计算都缺乏因果性的许可。

## 三个误区

1. **误区一：BERT 不能生成文本。** 准确的说法是，BERT 的预训练目标没教它生成。完形填空和续写是两种技能，前者看到的是完整句子，后者只能看到半边。社区很早就尝试过让 BERT 硬做续写，Stephen Mayhew 2019 年的实验输出的是 "much, ," 这种垃圾。但微调可以补上这条路，UNILM、MASS、BART 都把 MLM 思想改造成了生成目标，效果能达到可用，只是和原生自回归模型不在一个量级。所以"不能"应该改成"没学过，学起来也费劲"。

2. **误区二：GPT 训练时看不到未来信息。** 训练时整句在显存里。Sebastian Raschka 的表述最准确：整个训练序列都在内存里，是注意力掩码限制了每个位置能读什么。"看不到"不是物理事实，是数学约束的结果。

3. **误区三，也是最需要澄清的：mask 这个词的三重身份。** 中文语境里它至少指三样东西。第一，BERT 预训练用的 [MASK] 符号，它是替换输入词的 token，和注意力没有半点关系。第二，attention mask，屏蔽 padding 位置，因为 batch 里句子长度不一，补位的 0 不该参与注意力计算。第三，这一篇的主角 causal mask，锁定注意力方向的下三角偏置。三者都叫 mask，机制完全不同。HuggingFace 论坛上"attention mask 和 causal mask 有什么区别"的帖子有一万多浏览，说明这不是中文读者的独有困惑。

## 工程里的几条实践经验

掩码听着抽象，工程上全是具体操作。

1. **掩码是加法偏置，不是乘法。** HuggingFace 的 `get_extended_attention_mask` 把 1/0 掩码转成 0/大负数（早期用 -10000，现在用 dtype 最小值）的偏置矩阵，加到 softmax 之前。乘法掩码在 softmax 前做不到彻底屏蔽（0 乘以分数还是 0，但 softmax 的 e⁰ 问题还在），在 softmax 后又会破坏权重归一化。加法加负无穷是标准且严格正确的做法。

2. **现代实现里掩码矩阵常常根本不物化。** FlashAttention 的 `causal=True` 参数在 kernel 内部直接实现下三角逻辑，不生成显式的掩码矩阵，省一大笔显存。PyTorch 的 FlexAttention 走另一条路，用 `score_mod` 回调在分数上做判断，写一个 `torch.where(q_idx >= kv_idx, score, -float("inf"))` 就有因果掩码，还能和 FlashAttention 的性能对齐。

3. **句向量不要用 BERT 的 CLS pooler。** 拿 BERT 做句子嵌入时，[CLS] 后面那个线性层加 tanh 是为 NSP 任务训练的，直接用它做句向量效果反而差。Sentence-BERT 的实验结论是 mean pooling（对最后一层所有 token 求平均）通常更稳，E5 沿用了这套惯例；但 BGE 官方用的是 [CLS] 的最后一层隐状态，GTE 的模型卡配置的也是 CLS pooling。pooling 策略因模型而异，默认照搬 mean 反而会踩坑。这个坑不报错，只会静默拉低相似度质量。

4. **改掩码是可行的，但是非常规操作。** HuggingFace 论坛上有人想把 Llama 的因果掩码去掉做 NER，需要覆写 `_update_causal_mask` 或传自定义四维掩码。能改，但模型从没在这种注意力模式下训练过，改了之后的效果不保证，就像拿从未学过双向的模型硬吃双向红利。

## 2026：掩码不再非此即彼

2018 年之后，行业默认的分工稳定了近八年：理解任务用双向，生成任务用因果。2026 年上半年的一系列工作，把这张二选一的桌子掀了。

最响的一击来自 iLLaDA。这个 8B 模型（arXiv:2606.25331，2026 年 6 月）从头训练时用了全双向注意力，没有因果掩码。它把 MLM 的完形填空思想升级成了扩散生成：随机掩掉一部分 token，再一步步去掩码，最后长出完整文本。相比上一代扩散模型 LLaDA，报告的数字是 BBH +21.6（Base）、MATH +14.5 和 HumanEval +16.5（Instruct）；和同规模因果模型比，部分基准打平。**iLLaDA 的定位是 MLM 完形填空思想的生成化复兴，它证明"只有因果掩码才能生成"这个 2018 年以来很少被质疑的教条并不成立。** 双向注意力不再只服务理解任务，扩散过程给了它生成的能力。当然代价也在明面上：双向注意力的解码效率问题让它离落地还有距离，但路线本身的存在已经被证明。

第二股力量是掩码的区域化。DeepSeek-OCR 2（arXiv:2601.20552）的视觉编码器 DeepEncoder V2 用 Qwen2-0.5B 的 decoder 架构，却配了分块掩码：视觉 token 之间双向（图像没有天然的前后顺序，因果掩码会破坏空间对称性），查询 token 之间保持因果三角。一个 decoder 架构里双向和因果共存，OmniDocBench v1.5 拿到 91.09%。ZAYA1-VL（arXiv:2605.08560）在 LLM 内部对图像 token 放开双向、文本 token 保持因果，AI2D、ChartQA 涨了 1 到 3 分（论文同时报告部分感知与推理基准略有下降）。FocuSFT（arXiv:2605.09932）走训练技巧路线，微调长上下文模型时把上下文 token 放开双向、响应 token 保留因果，RULER 16K 的 CWE 指标从 72.9% 涨到 81.1%。这三项工作的共同结论是：掩码不再是架构属性，而是可以按 token 区域定制的矩阵。双向和因果正在从"两种模型"退化成"两种矩阵形状"。

第三股力量发生在嵌入模型这个细分战场，而且分成了两条互相矛盾的路。Qwen3-Embedding（2025 年 6 月发布）坚持 decoder-only 底座，保留因果掩码，用 last-token pooling 取向量，发布时在 MTEB 多语言榜以 70.58 分排第一。BidirLM（arXiv:2604.02045）反着来，把 Gemma3、Qwen3 这类因果模型改造成双向编码器，结论是"通过掩码目标启用双向注意力"是解锁微调性能的关键步骤。最分裂的是 Jina AI 开发、与 Elastic 合作发布的 jina-embeddings-v5-text（arXiv:2602.15547）：同一家族两个底座，small 版基于 Qwen3 系 decoder，nano 版基于 EuroBERT 系 encoder，两边下注。而阿里 2024 年 11 月在 GTE 系列的官方博客里明确表态：同规模下双向 encoder 在检索和排序上优于 decoder-only。嵌入领域七年的"BERT 系一统天下"被 Qwen3-Embedding 撕开之后，现在是真分裂了。

而所有想放开因果的尝试，最后都会撞上同一堵墙：KV cache。这是因果掩码最隐蔽的经济壁垒。bicache（arXiv:2606.07571）把原因讲得很清楚：因果掩码下，前缀的表示只依赖前缀自己，跨序列不变，缓存可以无脑复用；一旦放开双向，更新任何一个 token，全上下文的 K、V 全部改变，共享前缀缓存会直接精度崩溃。扩散语言模型的服务系统（Sangam，arXiv:2607.04206）暴露了双向在工程上的连锁反应：prefill 反复重算、KV 漂移、需要专用调度器。DualKV（arXiv:2605.15422）则证明了因果性的价值，因为 prompt 表示跨序列不变，RL 训练里共享 prompt 只需算一次，GRPO 训练的策略更新阶段提速 1.63 到 2.09 倍。所以主流生成模型（GPT 系、Llama 系、DeepSeek、Qwen）截至本文写作时全部保持全因果，不是没人想过放开，是效率账算不过来。

双向的老本行没有被撼动。EuroBERT 的官方新闻稿引过一个数字：BERT 在 HuggingFace 上仍以每月近 500 万次下载位居前列（2025 年 3 月），RAG、分类、句嵌入这些管线里的编码器需求依然稳定。理解这条路，BGE、GTE、ModernBERT 还在往下走。

## 一张表收束

| 维度 | 双向掩码（Encoder-only） | 因果掩码（Decoder-only） |
|------|--------------------------|--------------------------|
| 掩码矩阵 | 全 0，全开 | 下三角 |
| 代表模型 | BERT、ModernBERT、BGE | GPT、Llama、DeepSeek、Qwen |
| 预训练目标 | MLM 完形填空 | 自回归预测下一个词 |
| token 利用率 | 15% 位置产生信号 | 100% 位置产生信号 |
| 天然能力 | 理解：分类、问答、句嵌入 | 生成：续写、对话、代码 |
| 增量推理 | 表示依赖整句，无法高效复用 KV | KV cache 一次缓存永久有效 |
| 上下文长度 | 经典模型多在 512 token 量级（ModernBERT 等扩展到 8K） | 主流模型普遍支持 128K 以上 |
| 规模扩展 | 缺少成熟 scaling law，超大规模 encoder 罕见 | 有成熟 scaling law，规模扩展路径清晰 |

注：本表描述 2018–2025 年的经典分工；2026 年已出现掩码按 token 区域定制的混合形态（见上一节）。

## 结尾

回到开头那两个错觉。

"GPT 训练时看不到后面的词"，错在把物理和数学混为一谈。信息一直在显存里，是那张下三角矩阵把读取权收了回去。模型的每个判断，都是矩阵允许它看到的世界的产物。

"BERT 不能生成"，错在把没训练当成了不可能。iLLaDA 用 12 万亿 token 的从头训练证明，完形填空这条路走下去，一样能长出生成能力，只是解码的工程代价至今没有商业上可行的解法。

近八年前，一张矩阵的两种形状分出了两条路。2026 年，这两条路正在重新交汇：掩码从架构属性变成了可以逐区域定制的设计变量，理解与生成的边界，重新变回了一个开放问题。
