# 大模型的后训练之道：没动基座，6 倍提升从何而来

> **导读**：智谱 GLM-5.3 用同一个基座模型，纯靠后训练把 Terminal-Bench 3.0 从 4.6 拉到 28.3。这篇文章拆解后训练全链条——从 SFT 数据工程到 GRPO 算法、从 DPO 变体到环境合成，试图回答一个问题：后训练的瓶颈已经从模型转移到了环境，而大多数人对这件事的理解还停留在"调参数"的阶段。

2026 年 8 月 14 日，智谱发布 GLM-5.3，blog 开篇第一句写道："Scaling post-training is all we did"。同一个基座模型（GLM-5.2），没做预训练，没加参数，Terminal-Bench 3.0 从 4.6 涨到 28.3，DeepSWE v1.1 从 46.2 涨到 66.9。以上均为厂商自报；6× 的提升只发生在 Terminal-Bench 3.0 这一榜，同口径下 DeepSWE 约 1.45×，绝对分也仍低于 Fable 5 与 GPT-5.6 Sol。

这不是在说预训练不重要，而是说，后训练这件事的杠杆率已经高到你不重视它就很亏的程度。

## 预训练模型不会聊天这件事

一个预训练好的语言模型，本质上是一个"给定上文，预测下一个 token"的机器。它读过互联网上几乎所有文本，能续写、能填空、能模仿各种文体，但你给它发一条"帮我写个排序算法"的消息，它大概率会给你续写出"排序算法是计算机科学中的基础概念，常见的排序算法包括..."——因为它的训练数据里，这句话后面接的就是这段解释。

这就是预训练模型的本质缺陷：它学会了语言的模式，但没学会"对话"的模式。对话需要你理解指令、组织回答、控制长度、把握语气，甚至知道什么时候该拒绝。这些能力，预训练阶段大多没教。

后训练解决的就是这个问题。

> **后训练的本质不是教模型新知识，而是教它怎么用已有的知识与人交互。** 知识在预训练阶段就装进去了，后训练只是给它套上一层"助手"的行为规范。

这个判断来自 LIMA 论文（Zhou et al., 2023）的核心发现：只用 1000 条精心构造的指令-回复对做微调，模型就能在 65% 的情况下击败用人类反馈训练的 text-davinci-003（DaVinci003，175B 的 InstructGPT 模型）。他们把这个现象叫"表面对齐假说"（Superficial Alignment Hypothesis）——模型的行为风格是层薄薄的面具，预训练已经给了它面具底下的所有知识。

但 LIMA 的 1000 条数据能让你起步，却到不了 frontier。从"能聊天"到"能写代码、能解数学题、能操作工具"，中间隔着一套完整的后训练管线。

## SFT：后训练的第一道门

SFT（Supervised Fine-Tuning，监督微调）是后训练的第一步，做法很简单：收集一批"指令-回复"对，然后用标准的交叉熵损失训练模型，让它学会在给定指令下生成对应的回复。

但"怎么做"和"怎么做好"之间，差的是数据工程。

**数据质量 vs 数量**是个经典取舍。LIMA 说 1000 条就够了，Tülu 3（Allen AI, 2024）说 frontier 级别需要约 94 万条。两个结论都对，取决于你要到哪里。如果你的目标是"能用的聊天机器人"，500-2000 条专家手写数据确实够用；如果你要覆盖编程、数学、工具调用、安全对齐，那数据缺口是指数级的。

GLM-5.3 没有公开它的 SFT 数据规模，但从它的效果反推，数据工程的重点不在数量而在覆盖度：
- 编程需要能跑的代码
- 数学需要能验证的推理链
- 工具调用需要结构化的 API 描述

每一条数据都得是"对的"，而不只是"像的"。

**Loss masking**是 SFT 里最容易被忽略的细节。训练时只对"回复部分"计算损失，指令部分的 token 全部 mask 掉。如果不做这件事，模型会去学习"预测问题本身"，而不是"学习回答问题"。Llama 2 的论文里明确写了这个设计：prompt 和 answer 拼接后用分隔符隔开，prompt 部分不参与梯度更新。

还有一个"免费午餐"叫 NEFTune（arXiv:2310.05914）：在训练时给 embedding 向量加均匀噪声（α=5-15），LLaMA-2-7B + Alpaca 在 AlpacaEval 上的胜率从 29.8% 直接跳到 64.7%。原理没人完全说清，但效果是实打实的——对话质量的提升不来自"学得更多"，而来自"学得更稳"。

SFT 的产出是一个"会聊天"的模型，但它还不会"聊得好"。回答可能冗长、可能跑题、可能说错话还一本正经。要解决这些问题，需要进入偏好对齐阶段。

## RLHF：用奖励模型教模型"什么是好"

SFT 教模型"怎么说话"，RLHF（基于人类反馈的强化学习）教模型"怎么说得更好"。

RLHF 的管线分三步。第一步是 SFT。第二步是训练一个**奖励模型**（Reward Model, RM）：给 SFT 模型同一道题的两个不同回答，人类标注哪个更好，RM 学会给好回答打高分、差回答打低分。第三步是用 PPO（Proximal Policy Optimization）算法，让 SFT 模型在 RM 的指导下自我改进。

PPO 的目标函数长这样：

$$\max_{\pi_\theta}\;\mathbb{E}\big[r_\phi(x,y)\big] - \beta\,\mathbb{D}_{\text{KL}}\big[\pi_\theta\,\|\,\pi_{\text{ref}}\big]$$

翻译成人话：在最大化奖励分数的同时，别跑太远——KL 散度项把策略锚在 SFT 参考模型附近，防止它为了刷 RM 的分而输出乱七八糟的东西。

这个"防止跑偏"的设计不是摆设。Gao et al.（arXiv:2210.10760）用"黄金奖励函数"做实验，发现随着 PPO 训练推进，真实奖励先升后降——模型会找到 RM 的盲区，输出那些 RM 给高分但实际很烂的回答。这个现象叫**奖励过优化**（reward overoptimization），是 RLHF 最经典的失败模式。

RLHF 的工程复杂度很高。PPO 需要同时加载四个模型：
- 策略模型（正在训练）
- 参考模型（冻结的 SFT 版本）
- 奖励模型
- 价值/批评模型（用来估计 advantage）

7B 模型在 BF16 下光训练状态就要 112GB 显存，不用 FSDP 或 DeepSpeed ZeRO-3 根本跑不起来。

而且超参数极其难调。KL 系数 β 太小会奖励 hacking，太大则模型学不到东西。Llama 2 用 β=0.01（7B/13B）和 β=0.005（34B/70B），InstructGPT 用 β=0.02。学习率、clip 范围、GAE λ、batch size，每一个都在"稳定"和"效果"之间走钢丝。

RLHF 效果确实强——InstructGPT 1.3B 在人类偏好上击败了 175B 的 GPT-3。但它的复杂度和不稳定性，逼着不少团队去找更简单的替代方案。

## DPO：把奖励模型扔掉

2023 年 5 月，斯坦福的 Rafailov 等人发了一篇论文，标题就叫《你的语言模型其实是个隐藏的奖励模型》（arXiv:2305.18290）。核心发现是：RLHF 的 KL 约束奖励最大化目标，可以解析地重写为"策略模型 vs 参考模型的对数比率"，从而把奖励模型消掉。

DPO（Direct Preference Optimization，直接偏好优化）的损失函数：

$$\mathcal{L}_{\text{DPO}} = -\log\sigma\Big(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)} - \beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\Big)$$

不需要奖励模型，不需要 PPO 的四模型架构，只需要偏好对（好的回答 vs 差的回答）和一个冻结的参考模型。训练过程跟 SFT 一样稳定，效果在情感控制、摘要生成、对话任务上匹配甚至超过 PPO。

DPO 的隐含假设是：偏好数据来自参考模型附近（on-policy）。如果偏好对是从另一个更强的模型（比如 GPT-4）那里采的，参考模型根本没见过这类回答，对数比率会爆炸，训练就不稳定。Tülu 3 的做法是：偏好对从当前 SFT 模型自己生成的候选里采样，保持 on-policy。

但 DPO 有个臭名昭著的问题：**长度偏好**。因为隐含奖励是 β·log p(y|x)，更长的回答天然有更低的 per-token 概率，DPO 的优化会倾向于选更长的"好回答"，导致模型越训越啰嗦。

社区提出了几种修法：

- **SimPO**（arXiv:2405.14734）去掉参考模型，用长度归一化的平均 log-prob 作为 reward，再加一个目标 margin γ，在 AlpacaEval 2 上比 DPO 高 6.4 分。
- **LD-DPO**（arXiv:2409.06411）把似然拆成"公共长度部分"和"超长部分"，压低超长部分的权重。
- Tülu 3 用的是**长度归一化 DPO**，β 设到了 5（远高于 vanilla DPO 的 0.1），因为归一化改变了隐含奖励的尺度。

DPO 家族解决了一个工程问题：让中小团队不需要四卡 A100 的 PPO 集群也能做偏好对齐。但 DPO 是 offline 的——它只能从已有的偏好对里学，不能像 PPO 那样在线采样新回答、探索新策略。当你要突破 SFT 的天花板时，还是需要回到在线 RL。

## GRPO：DeepSeek 的答案

2024 年 2 月，DeepSeek 发了一篇关于数学推理的论文（arXiv:2402.03300），提出 GRPO（Group Relative Policy Optimization，群组相对策略优化）。

GRPO 的核心洞察是：PPO 里最难搞的 critic 模型（价值函数），其实可以用一个更简单的东西替代——同一道题的多个采样回答的相对分数。

具体做法：对每个问题 q，用当前策略采样 G 个回答（G=64），用奖励模型给每个回答打分，然后在组内做 z-score 归一化：

$$\tilde r_i = \frac{r_i - \text{mean}(\mathbf{r})}{\text{std}(\mathbf{r})}$$

归一化后的分数就是这个回答的 advantage。所有 token 共享同一个 advantage（outcome supervision），然后用 PPO 的 clipped surrogate 目标做更新。

去掉 critic 模型的改变是直接的：PPO 需要同时加载四个模型，GRPO 只需要三个（策略、参考、奖励）。显存直接省了 25%，而且不用训一个"猜每个 token 有多好"的价值函数——这个价值函数在只有最终奖励的场景下本来就很难训。代价是每题要采样 G 条回答，生成侧算力开销明显上升，25% 的显存节省也只是在同尺寸假设下的上界。

DeepSeek-R1（arXiv:2501.12948）把 GRPO 推到了新高度。R1-Zero 完全跳过 SFT，纯用 GRPO 做 RL 训练，证明了推理能力可以从 RL 中"涌现"。R1 则加了冷启动 SFT（几千条高质量推理链），先 RL，再 rejection sampling + SFT，最后再来一轮 RL。最终 R1 在 MATH-500 上拿了 97.3%，超过论文对比的 o1-0912（96.4）。

GLM-5.3 的 RL 阶段沿用 GLM-5.2 引入的 SAO（Single-Rollout Asynchronous Optimization）算法。但它的创新不在算法本身，而在于环境。

## 环境合成：后训练的真正瓶颈

GLM-5.3 的官方文档里有段话值得细读：

> "随着模型能力的提升，后训练的瓶颈已经从模型转移到了环境。一个有用的任务环境必须可执行、可验证、接近真实的专业工作。"

这句话的意思是：GRPO/DPO 这些算法本身已经够好了，真正缺的是"训练数据"——不是 SFT 那种静态的指令-回复对，而是能让模型在里头试错、拿到奖励信号、持续进化的**可执行环境**。

GLM-5.3 的做法是**多 Agent 环境合成**：
- 研究 Agent 从真实工作场景里挖掘任务模式，转成可运行的长程环境
- Judge Agent 尝试每个任务，验证它是否真的有解
- Verifier Agent 堵住奖励捷径（比如模型用某种 trick 绕过了真正的推理步骤但拿到了分）

一个 Verifier 必须通过 oracle（有解验证）、no-op（空操作）、unsolved-state（未解决状态）三项检查，才能产出可靠的二值奖励信号。官方也承认，这套管线仍依赖相当程度的人工介入，完全自主的环境生成与验证是它的下一步目标。

这套管线的逻辑跟 Anthropic 的 Constitutional AI（arXiv:2212.08073）精神相近——模型监督模型，而不是人监督人。区别在于 GLM-5.3 把"监督"从"给偏好对"升级到了"合成整个训练环境"。

这解释了为什么 GLM-5.3 能在 Terminal-Bench 3.0 上实现 6× 的提升——不是算法变了，而是它有了更多、更难的编程环境让模型去"刷题"。

> **后训练做到 2026，瓶颈不在算法，在环境。谁有最多、最可验证、最接近真实工作的训练环境，谁往往就能在后训练上走得更远。**

## 基础设施：异步 RL 的工程现实

环境合成解决了"训什么"的问题，但还有一个"怎么训"的问题。

传统的 PPO/GRPO 是同步的：采样一批回答 → 计算奖励 → 更新策略 → 再采样。采样阶段 GPU 在空等（生成文本用的是推理引擎，训练用的是训练引擎），GPU 利用率通常只有 30-50%。

GLM-5.3 开源的 **slime** 框架（github.com/THUDM/slime）用异步流水线解决了这个问题：Megatron 做训练，SGLang 做 rollout，两者在同一个数据流里并行。训练引擎在更新权重的同时，推理引擎已经在用旧权重生成下一批回答了。权重更新通过异步通信完成，训练-推理的一致性控制在 1e-7 的 logprob 差异以内。

结果是端到端 RL 训练吞吐量提升了 2.3 倍以上。

这不是 GLM 独有的趋势。VerlTool（arXiv:2509.01055）和 RLFactory（arXiv:2509.06980）这两个 2025 年涌现的 RL post-training 框架，也在做同一件事：把训练和推理解耦，让环境交互、奖励计算、策略更新并行起来。

## 蒸馏与量化：后训练的最后一公里

训练完成不等于能用。模型还要经过蒸馏和量化，才能以可接受的成本部署上线，这是后训练管线的最后一公里。

**蒸馏**的核心思想是用大模型（teacher）教小模型（student）。传统 KD 让小模型去拟合 teacher 的 token 级别分布，但 MiniLLM（Gu et al., 2023, arXiv:2306.08543）发现这会让弱模型过度覆盖 teacher 的长尾分布，导致退化。他们改用 reverse KL（mode-seeking），让小模型聚焦在 teacher 的高概率模式上，而不是试图覆盖整个分布。

**量化**把模型从 FP16/BF16 压到 INT8/INT4，降低推理成本。AWQ（Lin et al., 2023）发现保护 1% 的"显著"权重（按激活量级识别）就能大幅降低量化误差，是当前实践中的主流方案之一。

DeepSeek-V4 在 post-training 阶段就引入了 FP4 量化感知训练（QAT），让权重在训练时就适应低精度，而不是训练完再量化。这是后训练和部署管线融合的一个信号。

## 后训练的终局不是算法

GLM-5.3 没动基座，纯靠后训练实现了 6× 提升。它靠的不是新算法。

GRPO 来自 DeepSeek，DPO 来自斯坦福，异步 RL 是工程优化，蒸馏量化是成熟技术。GLM-5.3 的真正贡献是把这些组件串成了一条管线，然后用环境合成解决了"数据从哪来"的问题。

这大概是 2026 年后训练领域最重要的认知转变：**瓶颈从"怎么训"转移到了"训什么"**。

InstructGPT 时代，PPO 的稳定性是瓶颈。DPO 时代，偏好数据的质量是瓶颈。GRPO 时代，奖励信号的可靠性是瓶颈。到了 GLM-5.3 和 DeepSeek-V4 的时代，瓶颈变成了"你有没有足够多、足够难、可验证的训练环境"。

算法的进步让后训练的天花板越来越高，但天花板的高度取决于你能给它喂什么样的数据。当模型能在你合成的环境里刷完所有题，下一步是把环境合成推进到更接近真实工作流的场景。
