# 从 MLP 到 Mamba：二十年序列建模，争的一直是同三样东西

> **导读**：序列建模架构的每一次更替，看起来像"下一代更强"，实际是三根轴在反复重新分配。第一根是信息路径，决定任意两个位置之间传话要走几步、信号能不能穿过；第二根是训练并行度，决定 GPU 能不能吃饱；第三根是推理状态大小，决定部署时显存涨不涨。MLP 装不下变长序列，RNN 换来了任意长度却交出了并行度，LSTM 补上了跨时间步的梯度通路，ConvLSTM 把状态从标量换成特征图，Transformer 用随长度增长的 KV cache 换来了 O(1) 的信息路径。到了 2026 年，xLSTM、Mamba、RWKV 各自把其中一根轴推到了尽头，LSTM 的能力并没有消失，只是拆开装进了不同的模型。

LSTM 早就不是序列建模的唯一答案了。值得讨论的是"LSTM 的哪些东西被继承、哪些东西被丢掉"。很多讨论把这件事简化成"注意力赢了循环"，但这个说法既不完整，也不准确。Transformer 确实解决了循环网络的两个大麻烦，可它自己带来的新麻烦在 2024 年之后又被另一批模型接走了。绕一圈下来，被反复争夺的其实一直是同样三样东西。后面每一节都要回到同样的三个坐标：路径长度、训练并行度、推理状态大小。

## 一、固定长度是一道墙

MLP 用来处理序列的第一个障碍不在于它学不会，而在于它的输入必须先变成一个固定维度的向量。权重矩阵的形状在训练前就定死了，序列长度一变，输入维度跟着变，模型得重建。网络不会处理"长度"，只会处理"形状"。

工程上的通用解法是 padding。Kim 2014 做句子分类时把句子补齐到固定长度，论文里的表述是 "A sentence of length n (padded where necessary)"（arXiv:1408.5882）。这个做法能跑通，代价却是三重的：

- 补齐的位置照样参与运算，batch 内长度分布越散，算力浪费越大
- 模型得额外学一套"哪些位置该忽略"的判断
- 全连接对输入各位置是对称的，本身不含顺序概念，"猫吃鱼"和"鱼吃猫"在它眼里是同一个向量

第三条最麻烦，因为顺序信息丢在架构里，不是靠加个位置向量就能补回来的。MLP-Mixer 后来给出一个有意思的中间形态：它把序列看成 S 个 token，用一组参数在 token 维度上做混合，作者自己承认这个设计"可以看作一种特殊的 CNN，用 1×1 卷积做通道混合，用全感受野的参数共享深度卷积做 token 混合"（arXiv:2105.01601）。意思很清楚：MLP 想碰序列，就得先把卷积的两样武器（参数共享、感受野）重新造一遍。

从第一根轴看，MLP 的处境是路径长度 O(1) 但要求固定维度，训练能完全并行、推理没有状态。这个组合在短文本分类上其实够用，输在需要变长、需要顺序的地方。

## 二、把状态传下去

RNN 的解法是引入一个状态向量，让它沿着时间步往下传。展开之后，一个 RNN 单元在每个时刻被复制成 T 份，用的是同一组参数。Graves 在 2008 年的专著里把这件事说得很清楚：展开后的 RNN 就是一个带权重共享的深层前馈网络（Graves, *Supervised Sequence Labelling with Recurrent Neural Networks*）。

这个参数共享是 LSTM 能处理变长序列的根本原因，也是它参数量与序列长度无关的原因。代价出现在两个地方。

第一个代价是梯度。误差反向传播时，要沿着时间步连乘 Jacobian 矩阵，训练中踩到的那个经典坑来自 Bengio 等人 1994 年的分析：误差随时间的演化对权重大小呈指数依赖（Bengio et al., *Learning long-term dependencies with gradient descent is difficult*, IEEE TNN 5(2):157-166, DOI 10.1109/72.279181）。Pascanu 等人后来给出了精确的判据：循环权重矩阵的最大特征值 λ₁ 小于 1 时，长程分量随时间指数消失；大于 1 时指数爆炸（arXiv:1211.5063）。消失意味着模型学不到相隔很远的相关，爆炸意味着权重来回震荡。

第二个代价是训练并行度。RNN 每一步的计算都依赖上一步的输出，整条链拆不开。GPU 有上千个核心，一条长度几百的序列却只能一步一步走。Transformer 论文在对比循环层时给出的复杂度是 O(n·d²) 每层、O(n) 次顺序操作、最大路径长度 O(n)（arXiv:1706.03762，Table 1），后两项正是这里说的并行度和路径长度。

所以 RNN 换来任意长度，代价是把并行度和路径长度同时交了出去。第二根轴上它交了白卷，第三根轴上它反而领先：状态大小与序列长度无关。

## 三、加性路径：LSTM 真正发明的东西

LSTM 的三个门大家都很熟，公式也背得出来。真正被发明出来的核心，是细胞状态那条加法路径。

```
i_t = σ(W_ii x_t + b_ii + W_hi h_{t-1} + b_hi)
f_t = σ(W_if x_t + b_if + W_hf h_{t-1} + b_hf)
g_t = tanh(W_ig x_t + b_ig + W_hg h_{t-1} + b_hg)
o_t = σ(W_io x_t + b_io + W_ho h_{t-1} + b_ho)
c_t = f_t ⊙ c_{t-1} + i_t ⊙ g_t
h_t = o_t ⊙ tanh(c_t)
```

关键在倒数第二行。c_t 的更新是**加法**的，旧状态只被 f_t 逐元素缩放，不被任何矩阵乘混合。梯度沿着这条路回传时，∂c_t/∂c_{t-1} 就是一个对角矩阵，对角元正是 f_t。这是 LSTM 与普通 RNN 在机制上最要紧的一处差别，别的都是它的衍生。

把它写出来最直观：

```python
import torch

def lstm_cell(x, h_prev, c_prev, W_ih, W_hh, b_ih, b_hh):
    """手写 LSTM cell，把加性路径摊开（对照 PyTorch 的 nn.LSTMCell）"""
    gates = x @ W_ih.T + h_prev @ W_hh.T + b_ih + b_hh
    i, f, g, o = gates.chunk(4, dim=-1)
    i, f, o = torch.sigmoid(i), torch.sigmoid(f), torch.sigmoid(o)
    g = torch.tanh(g)
    c_new = f * c_prev + i * g      # 加性路径：旧状态只被 f 逐元素缩放
    h_new = o * torch.tanh(c_new)
    return h_new, c_new

def lstm_sequence(x_seq, h0, c0, W_ih, W_hh, b_ih, b_hh):
    """按时间步循环，保留每一步的 f，用来观察梯度路径"""
    h, c = h0, c0
    h_list, c_list, f_list = [], [], []
    for t in range(x_seq.size(0)):
        gates = x_seq[t] @ W_ih.T + h @ W_hh.T + b_ih + b_hh
        i, f, g, o = gates.chunk(4, dim=-1)
        i, f, o = torch.sigmoid(i), torch.sigmoid(f), torch.sigmoid(o)
        g = torch.tanh(g)
        c = f * c + i * g
        h = o * torch.tanh(c)
        h_list.append(h); c_list.append(c); f_list.append(f)
    return torch.stack(h_list), torch.stack(c_list), torch.stack(f_list)
```

拿到每一步的 f 之后，梯度路径是可以直接验的：

```python
h_seq, c_seq, f_seq = lstm_sequence(x, h0, c0, W_ih, W_hh, b_ih, b_hh)
# c_{T} 对 c_{T-1} 的雅可比是对角阵，对角元就是 f_{T-1}（逐元素，不是矩阵乘）
jac = torch.autograd.grad(c_seq[-1].sum(), c_seq[-2],
                           grad_outputs=torch.ones_like(c_seq[-1]))
```

`jac` 的每个对角元素约等于对应的 f 值。这个性质是理解 LSTM 几乎全部优势的钥匙：梯度不会在时间步之间被矩阵乘放大或缩小，只会被逐元素地乘上一个小于 1 的数。

### 这条路径从哪来

Hochreiter 和 Schmidhuber 1997 年的原文推导过这件事。他们的目标是让误差信号以恒定的强度流过细胞内部的一个特殊单元，条件写成 `f'_j(net_j(t)) · w_jj = 1.0`：激活函数必须线性，且自连接权重必须等于 1.0。他们把这个结构称为常数误差流（constant error carousel, CEC）。论文摘要里的表述是，LSTM 通过强制恒定误差流，"可以学习跨越超过 1000 个离散时间步的最小时间滞后"（Hochreiter & Schmidhuber, *Long Short-Term Memory*, Neural Computation 9(8):1735-1780, DOI 10.1162/neco.1997.9.8.1735）。

这里有两个限定条件经常被丢掉。一是"超过 1000 步"指的是人工构造的长滞后任务，不是自然语言或真实传感器数据上的表现；二是原文明说了截断的必要：误差信号一旦想离开细胞或门单元就被切断，因为"error flow is truncated once it 'wants' to leave memory cells or gate units"。CEC 之所以能成立，前提正是误差不许乱跑。

换句话说，LSTM 不是"解决了梯度消失"，而是把梯度消失这条路上最陡的一段改成了平路。

### 三个门分别在做什么

Greff 等人 2015 年系统消融了八种 LSTM 变体，结论有两条值得记住。第一，八个变体里没有一个能显著超过标准 LSTM，论文的措辞是 "none of the variants can improve upon the standard LSTM architecture significantly"（arXiv:1503.04069）。第二，遗忘门和输出激活函数是最关键的两个组件，去掉任何一个都会显著掉点。

遗忘门是 2000 年才补上的。原始 LSTM 没有遗忘机制，处理连续无分段的数据流时状态会无限膨胀直到崩溃，Gers 等人 2000 年的 "Learning to Forget" 补上了这个门，让细胞状态学会自我重置（Neural Computation 12(10):2451-2471, DOI 10.1162/089976600300015015）。

这个门的初值有个不大不小的坑。PyTorch 的 `RNNBase.reset_parameters` 对所有参数统一做 U(-1/√hidden_size, 1/√hidden_size) 的均匀初始化（`torch/nn/modules/rnn.py`），遗忘门的偏置因此是个接近 0 的随机数，经过 sigmoid 之后落在 0.5 附近。这意味着每一步的梯度都乘上大约 0.5，走 100 步就是 0.5 的 100 次方量级。Jozefowicz 等人 2015 年的建议是给遗忘门加 1 的偏置，让它初始接近 1，论文里说得很直接："we recommend adding a bias of 1 to the forget gate of every LSTM in every application"，并且指出这一做法能把 LSTM 与 GRU 的差距抹平（Jozefowicz et al., *An Empirical Exploration of Recurrent Network Architectures*, ICML 2015, PMLR v37:2342-2350）。这个建议不是 PyTorch 的默认行为，需要手动写。

### LSTM 没有解决的那部分

上面说的都是工程意义。统计意义上，RNN 和 LSTM 并不具备真正的长记忆。Zhao 等人 2020 年证明，带 Markov 型更新动力学的循环网络过程只有短记忆，真正的长记忆要求权重按多项式速率衰减（arXiv:2006.03860）。他们提出的修正方案是在网络里加一个记忆滤波器，让 RNN 和 LSTM 变成所谓的长记忆网络。

更近一点的研究还指出，梯度消失和爆炸并不是 RNN 训练困难的全部。Zucchet 和 Orvieto 发现，随着网络要编码的记忆变长，参数的一点微小变化会引起越来越大的输出波动，即便动力学本身是稳定的，也就是说基于梯度的方法对这些网络高度敏感（arXiv:2405.21064）。LSTM 的逐元素递归设计在这件事上比一般循环网络更能扛，但隐患依然存在。

## 四、把卷积塞进 cell

LSTM 有两个逃不掉的短板：状态是一个标量向量，容量有限；记忆混合（hidden 到 hidden 的连接）让它没法并行。2015 年之后，一批工作分别从这两个方向动手。

### ConvLSTM：卷积嵌进单元内部

ConvLSTM 与普通 LSTM 的差别只有一处，但它很关键：把 FC-LSTM 中 input-to-state 和 state-to-state 的逐点矩阵乘换成卷积算子（Shi et al., *Convolutional LSTM Network: A Machine Learning Approach for Precipitation Nowcasting*, arXiv:1506.04214）。全部输入、细胞输出、隐状态和三个门都变成三维张量，最后两维是空间行列。

```
i_t = σ(W_xi * X_t + W_hi * H_{t-1} + W_ci ∘ C_{t-1} + b_i)
f_t = σ(W_xf * X_t + W_hf * H_{t-1} + W_cf ∘ C_{t-1} + b_f)
C_t = f_t ∘ C_{t-1} + i_t ∘ tanh(W_xc * X_t + W_hc * H_{t-1} + b_c)
o_t = σ(W_xo * X_t + W_ho * H_{t-1} + W_co ∘ C_t + b_o)
H_t = o_t ∘ tanh(C_t)
```

细胞状态不再是向量，而是 `R^{C×H×W}` 的特征图。网格上每个位置是一个"细胞"，它的更新只依赖局部邻域，卷积的感受野决定了它能看多远。状态大小这一轴在这里第一次被真正撑开了。

论文的原始场景是降水临近预报：输入是雷达回波图序列，输出是未来若干帧。雷达数据集上 15 步预测的平均 CSI，ConvLSTM 是 0.577，业务界的 ROVER2 算法是 0.522，FC-LSTM 只有 0.286。

精简实现如下，核心就是把矩阵乘换成卷积：

```python
import torch
import torch.nn as nn

class ConvLSTMCell(nn.Module):
    """ConvLSTM 单元：把 FC-LSTM 的矩阵乘换成卷积，状态变成特征图"""

    def __init__(self, in_channels, hidden_channels, kernel_size):
        super().__init__()
        self.hidden_channels = hidden_channels
        self.padding = kernel_size[0] // 2, kernel_size[1] // 2
        # 两套卷积：input-to-state 与 state-to-state，各自输出四个门
        self.conv_x = nn.Conv2d(in_channels, 4 * hidden_channels, kernel_size, padding=self.padding)
        self.conv_h = nn.Conv2d(hidden_channels, 4 * hidden_channels, kernel_size, padding=self.padding)

    def forward(self, x, h_prev, c_prev):
        gates = self.conv_x(x) + self.conv_h(h_prev)
        i, f, g, o = gates.chunk(4, dim=1)
        i, f, o = torch.sigmoid(i), torch.sigmoid(f), torch.sigmoid(o)
        g = torch.tanh(g)
        c = f * c_prev + i * g      # 细胞状态是特征图，加法路径不变
        h = o * torch.tanh(c)
        return h, c
```

注意 `conv_x` 和 `conv_h` 是两套独立参数，这是 ConvLSTM 相对 FC-LSTM 的结构改动，而加法路径本身原封不动。换句话说，卷积解决的是"状态装不下"和"看不到空间关系"，没解决任何梯度问题。

原文的 FC-LSTM 基线还带了 peephole 连接（门能直接看到细胞状态），现代实现包括上面这段代码通常都不带。Greff 等人的消融结论是，去掉 peephole 不显著影响性能，参数量和计算量反而更低，所以这不是个需要担心的差异。

### 工程上更常见的另一种拼法

国内落地较常见的一种做法是把 CNN 和 LSTM 串起来：CNN 先抽局部特征，BiLSTM 再建长程上下文。Rhanoui 等人 2019 年在文档级情感分析上用的就是这个结构（DOI 10.3390/make1030048）。这类拼法的好处是模块化，CNN 部分可以直接换预训练模型；代价是特征在进 LSTM 之前就被压成了固定维度，空间结构信息在这一步丢掉了。

卷积与循环融合的第三种形态是 QRNN（Bradbury et al., arXiv:1611.01576）。它交替使用两个组件：卷积组件沿时间步并行，同时算出候选向量和门；递归池化组件无参数，沿通道并行。关键设计是 masked convolution，输入左侧填充卷积核大小减一，保证 t 时刻只看到 t-k+1 到 t，不泄露未来。

论文里有两个值得记的事实：一是它"没有任何可训练的递归层"，精度却优于同 hidden size 的堆叠 LSTM；二是由于并行度高，训练和测试最多快 16 倍，但这个数字是相对 cuDNN 优化过的 LSTM、在特定 batch 和序列长度下测出的，IMDb 任务上的实测只有 3.2 倍。

### 今天的 ConvLSTM 还剩什么位置

2023 年一项人体活动识别的对比里，单帧 CNN 在 UCF50 上拿到 99.8% 的准确率，反而超过了 ConvLSTM（arXiv:2304.14499）。当任务的判别信息在单帧里已经足够时，把序列模型加上去只是增加负担。

在气象领域，ConvLSTM 的原始主场也已经换了算法。GenCast 是条件扩散模型，denoiser 走 encoder-processor-decoder 三段式，processor 是在六倍细化的二十面体网格（41162 个节点）上做邻域注意力的 graph transformer，16 层标准 Transformer 块（arXiv:2312.15796）。时空预测这条线上，卷积加循环的组合基本让位给了注意力加三维结构。

## 五、读未来，但只能在读完之后

在注意力成为默认选项之前，还有一条至今仍在分类和标注任务里大量使用的分支：让序列从两个方向各读一遍。BiLSTM 是 Schuster 和 Paliwal 1997 年提出的，结构上没什么新东西：正向 RNN 和反向 RNN 各跑一遍，输出拼起来。论文摘要里的关键句是，它"可以训练而不再受限于只能使用到某个预设未来帧为止的输入信息"（Schuster & Paliwal, *Bidirectional Recurrent Neural Networks*, IEEE TSP 45(11):2673-2681, DOI 10.1109/78.650093）。

把这句反过来读，就得到了 BiLSTM 全部的适用边界：它需要完整序列。在线推理、流式处理、自回归生成，这三种场景里反向那一路根本算不出来，因为未来的帧还不存在。

PyTorch 文档里有一个容易踩的细节：双向 LSTM 的 `h_n` 不等于 `output` 的最后一个元素，前者包含正向和反向的最终隐状态，后者包含正向的最终隐状态和反向的初始隐状态。这是从"反向 RNN 从序列末尾往前跑"直接推出来的。

## 六、Transformer 记的账

双向这条路的边界到此为止。Transformer 在三根轴上的位置，Vaswani 等人 2017 年的 Table 1 说得比任何二手转述都清楚（arXiv:1706.03762）：

| 层类型 | 每层复杂度 | 顺序操作次数 | 最大路径长度 |
|---|---|---|---|
| 自注意力 | O(n²·d) | O(1) | O(1) |
| 循环 | O(n·d²) | O(n) | O(n) |
| 卷积 | O(k·n·d²) | O(1) | O(log_k n) |

路径长度是这张表的第三列，含义是任意两个位置之间传递信息需要经过多少层。自注意力是 O(1)，因为任意两个位置之间一次注意力就算完了，不需要一层一层传；循环是 O(n)，因为第一个 token 的信息要走 n 步才能到最后一个 token。训练并行度看第二列，自注意力是 O(1) 次顺序操作，也就是整条序列一次矩阵乘算完。循环的 O(n) 次顺序操作，正是 GPU 吃不饱的原因。

代价出现在第三根轴上。自回归生成时，每生成一个 token 都要对全部历史做一次注意力，单步成本是 O(n)，而且历史要留着，KV cache 随上下文长度线性增长。循环网络每步只更新一个固定大小的状态，单步成本 O(1)，显存不随长度涨。这是循环网络到今天仍有一席之地的原因。

还有一件事常被说错。2020 年 Katharopoulos 等人证明线性注意力可以写成循环递推的形式，结论是"任何带因果掩码的 Transformer 层都可以写成一个给定输入、修改内部状态、然后预测输出的模型，也就是一个循环神经网络"（arXiv:2006.16236）。所以注意力和循环不是对立关系，而是同一个递推结构的两种写法。这篇论文里"最多快 4000 倍"的说法有严格限定：指的是自回归生成、超长序列场景下的最大加速比，原文另有一处表述是"推理时快至三个数量级"，速度实验跑在 GTX 1080 Ti 上、序列长度从 2⁹ 到 2¹⁶，softmax 在那块 11GB 显存的卡上最长只到 4096。这不是训练加速，也不是普适结论。

第三根轴还有另一面。Transformer 路线为了突破训练时的上下文窗口，补了一系列外推方法：RoPE（arXiv:2104.09864）、位置插值把 LLaMA 的上下文扩到 32768（arXiv:2306.15595）、YaRN（arXiv:2309.00071）。循环网络的状态大小固定，天然没有这个问题，但它换来的是压缩记忆，而不是精确检索。

## 七、LSTM 的能力被谁接走了

LSTM 的四项长处，在 2024 到 2026 年被拆开，分别由不同模型接手。

1. **梯度能跨长序列**，由 xLSTM 接手。做法是指数门控加矩阵记忆：sLSTM 保留标量记忆并新增记忆混合，mLSTM 把细胞状态升级成 `d×d` 的矩阵，用协方差（外积）更新规则，完全可并行。xLSTM 论文的消融表把这笔账算得很清楚（arXiv:2405.04517，Table 2）：vanilla LSTM 在 15B token 的 SlimPajama 上验证集困惑度是 2417.86，换上 xLSTM 骨架后降到 26.01，加上指数门控降到 17.70，再加上矩阵记忆降到 13.48。同规模的其他方法里，Mamba 是 13.70，Llama 是 14.25（Table 1）。外推能力上差距更大：1.3B 模型上，训练上下文 2048、测到 16384 时，Llama 的困惑度是 337.83，xLSTM[7:1] 是 8.92（Figure 7）。这个模型后来扩到了 7B，论文自称在他们的推理效率基准上是最快的 7B 模型（arXiv:2503.13427，ICML 2025）。

2. **训练要能并行**，由 Mamba 和 Mamba-2 接手。Mamba 的做法是让状态空间模型的参数成为输入的函数，模型因此可以按当前 token 选择性地传播或遗忘信息，代价是失去了高效卷积形式，论文为此设计了硬件感知的并行扫描算法（arXiv:2312.00752）。摘要报告生成吞吐是相似规模 Transformer 的 5 倍，性能在真实数据上可扩展到百万长度序列。Mamba-2 用结构化状态空间对偶（SSD）框架把这套东西重新组织了一遍，核心层比 Mamba 的扫描层快 2 到 8 倍，同时允许 8 倍大的循环状态（arXiv:2405.21060）。这里的 2 到 8 倍是层对层的比较，不是端到端模型速度，论文自己也承认在 2K 这样的短序列上 Transformer 可能更快。它给出的混合比例参考是：350M 规模模型上纯 Mamba-2 的困惑度是 8.60，插入 6 层注意力后降到 8.26，约 10% 的注意力层比例最优。

3. **推理状态恒定**，由 RWKV-7 接手。RWKV-7 "Goose" 用广义 delta rule 加向量值门控和上下文学习率，摘要的表述是"常数内存占用和每 token 常数推理时间"，训练规模从 0.19B 到 2.9B，语料 3.1 万亿 token（arXiv:2503.14456）。同类的还有 Google DeepMind 的 Griffin，把门控线性递归和局部注意力混在一起（arXiv:2402.19427），以及把测试时训练当记忆用的 Titans，论文报告它能扩展到 200 万以上的上下文（arXiv:2501.00663）。

4. **精确检索长上下文的能力**，谁也没抢走，全靠混合架构保留。这恰好说明了三根轴是此消彼长的关系，不是单轴通关。

循环架构在改造自己的同时，CNN 路线那边也在复活。TCN 论文的结论相当直接：一个简单的卷积架构在多种任务和数据集上超过 LSTM 和 GRU，而且有效记忆更长，作者据此主张"序列建模与循环网络的绑定关系应该被重新审视，卷积网络应当被当作序列建模任务的自然起点"（arXiv:1803.01271）。ModernTCN 把它推得更远，纯卷积结构在长短期预测、插补、分类、异常检测五类任务上取得一致的最好结果，关键洞察是**大 kernel 比堆叠小 kernel 更能扩大有效感受野**（ICLR 2024 Spotlight）。

还有一条路是把 LSTM 自己改回能并行。2024 年的 "Were RNNs All We Needed?" 把 LSTM 和 GRU 拆到只剩骨架：去掉门对前一步隐状态的依赖，再去掉限制输出范围的 tanh，得到 minLSTM 和 minGRU。这两个模型不再需要通过时间反向传播，可以完全并行训练，论文报告在长度 512 的序列上，minGRU 比 GRU 快 175 倍、minLSTM 比 LSTM 快 235 倍（T4 GPU，每训练步），参数量也更少，精度却能和 Transformer、Mamba 打得平（arXiv:2410.01201）。这也说明 LSTM 的问题不一定非得靠换架构解决，砍掉一部分能力有时候就够了。

框架层面的变化更微妙。HuggingFace Transformers 在 2020 年就删掉了 `Model2LSTM` 这个 LSTM decoder 类，理由写在当年的发布说明里："Removed untested `Model2LSTM` and `Model2Model` which was not working"。2023 年有人提 issue 要求把它加回来，一位贡献者的回复是，除了那次删除之外没有人再要求过这类模型，同时指向当时刚加入的 RWKV。此后 Transformers 维护的循环家族包括 RWKV、Mamba/Mamba2、xLSTM（2025 年 7 月 25 日合入，PR #39665）、RecurrentGemma、Jamba、Zamba 等，并没有通用的 LSTM 类。

Keras 那边给出的答案不同：PyTorch 后端的 cuDNN 支持在 2025 年 4 月合并（PR #21135），作者贴的自测基准是平均加速 15.11 倍、中位数 11.53 倍。换句话说，框架层面对 LSTM 的态度不是废弃，是不再为它单独投入。

## 八、今天该选什么

下表按场景给建议，每一行都对应前面某一根轴上的取舍。

| 场景 | 建议 | 依据 | 代价 |
|---|---|---|---|
| 长文档理解、分类、抽取 | Transformer 编码器 | 路径长度 O(1)，并行训练 | KV cache 与推理显存随长度涨 |
| 实时流式预测，逐 token 出结果 | LSTM/GRU、RWKV-7、Mamba | 推理状态恒定，单步 O(1) | LSTM 训练串行，长序列能力弱 |
| 结构化数值时序预测 | 先试 TCN/ModernTCN | 有效记忆长，完全并行 | 感受野固定，长依赖靠扩张卷积堆 |
| 视频、雷达的时空预测 | 三维注意力模型或 ConvLSTM | 需要空间结构加时间结构 | ConvLSTM 参数量和显存开销大 |
| 边缘设备、小模型、低延迟 | LSTM/GRU | 部署链成熟，cuDNN/TFLite 支持完善 | 表达能力上限低 |
| 需要在长上下文里精确检索 | Transformer 加外推方法 | 注意力保留精确寻址 | 外推方法本身是补丁，效果不稳 |

表格之外还有几条：

- **BiLSTM 只在完整序列已知时用**。句级分类、NER、离线标注这类任务适合，流式和自回归场景基本不适用。
- **LSTM 和 GRU 差距比想象中小**。GRU（门控循环单元）把 LSTM 的输入门和遗忘门合成一个更新门，再加一个重置门，参数量只有 LSTM 的四分之三左右（arXiv:1406.1078）。Greff 的消融显示遗忘门加输出激活是最关键的，输入输出门的差异影响有限；实际项目里两者都试一遍通常就够了。
- **数据量小的时候别用大模型**。LSTM 在小数据上容易过拟合，预测结果会向滞后移动，这时传统统计方法（ARIMA 类的指数平滑）可能更合适。

## 九、PyTorch 里的正确姿势

选型定下来之后，代码怎么写对是另一件事。下面只讲 API 层面的坑。

第一个坑是变长序列。默认的 `nn.LSTM` 会把 padding 位置照常喂进去，污染后续时间步的隐状态。`pack_padded_sequence` 是解法，但要注意它只保证 RNN 不计算 padding 位，**不保证 loss 忽略 padding**，标签侧要么一起 pack，要么用 `ignore_index`：

```python
import torch
import torch.nn as nn
from torch.nn.utils.rnn import pack_padded_sequence, pad_packed_sequence

lstm = nn.LSTM(input_size, hidden_size, num_layers=2, batch_first=True)

def forward(tokens, lengths, labels):
    # 输入侧：打包，RNN 不再计算 padding 位
    packed = pack_padded_sequence(tokens, lengths, batch_first=True,
                                 enforce_sorted=False)
    out_packed, _ = lstm(packed)
    out, _ = pad_packed_sequence(out_packed, batch_first=True)

    # 标签侧二选一：
    # 方案 A，把标签也 pack，直接对 packed 输出算 loss，padding 位根本不存在
    # 方案 B，在补齐后的张量上算 loss，用 ignore_index 排除 padding
    loss = nn.functional.cross_entropy(out.reshape(-1, num_classes),
                                        labels.reshape(-1),
                                        ignore_index=-100)
    return loss
```

`enforce_sorted=False` 让 PyTorch 内部按长度降序重排，`sorted_indices` 记录这次重排，`unsorted_indices` 负责还原。LSTM 返回的 `h_n` 和 `c_n` 已经按 `unsorted_indices` 还原回原始 batch 顺序，所以上层代码不用自己处理。官方文档的 Note 里还有一句容易漏的话：这个函数接受至少两维的输入，所以标签可以直接打包，用 RNN 的输出配它算 loss。

第二个坑是遗忘门的初始偏置。PyTorch 默认不给，需要手动写，而且 PyTorch 有 `bias_ih` 和 `bias_hh` 两个偏置项（后者是为了兼容 cuDNN 加的），两个都得设：

```python
def init_forget_gate_bias(lstm, value=1.0):
    """把遗忘门偏置设为正值，让门初始接近 1，梯度能跨长序列"""
    for name, param in lstm.named_parameters():
        if "bias_ih" in name or "bias_hh" in name:
            n = param.size(0)
            # 门顺序是 (i, f, g, o)，遗忘门是第 2 段
            param.data[n // 4: n // 2].fill_(value)
```

第三个坑是 `batch_first`。它默认是 `False`，也就是输入是 `(seq, batch, feature)`。官方文档明写了一句 "this does not apply to hidden or cell states"，意思是 `h_n` 和 `c_n` 始终是 `(num_layers*num_directions, batch, hidden_size)`，不受 `batch_first` 影响。`batch_first=True` 时输出的 `out` 还可能不连续，后面接 `.view()` 会报错，需要 `.contiguous()`。

第四个坑是 `dropout`。这个参数只在层间生效（除最后一层外），而且只在 `model.train()` 下生效，`num_layers=1` 时 PyTorch 会直接 warn 提示这个参数没有意义。`nn.LSTMCell` 这一层级的 API 干脆没有 dropout 参数。

cuDNN 那条路径也有边界。PyTorch 源码里的启发式显示，走 persistent 算法需要满足几个条件（`aten/src/ATen/native/cudnn/RNN.cpp`）：

- 单层、单向
- hidden_size 不超过 1024 且能被 128 整除
- input_size 能被 128 整除
- 输入是 fp16，且不能用 packed 输入

还要过一批按 GPU 架构和 batch size 设置的设备启发式；走小 hidden 的 persistent 变体时，LSTM 前向要求 hidden_size 不超过 192，反向不超过 128。这些是启发式的 bail-out，不是硬报错，所以表现是"没走快路径"而不是"崩"。真正的硬限制是序列长度：cuDNN 在长度 65536 时会直接报 `CUDNN_STATUS_NOT_SUPPORTED`（PyTorch issue #133751），官方 workaround 是把序列切成 65535 长度的块。

梯度裁剪用 `clip_grad_norm_` 而不是 `clip_grad_value_`。前者把所有参数的梯度拼成一个向量算总范数再等比缩放，保持方向不变；后者逐元素截断，会改变梯度方向。Jozefowicz 等人在超参搜索里用的候选值是 1、2.5、5、10、20，PyTorch 官方 word_language_model 示例的默认值是 0.25。

最后是混合精度。cuDNN 的 RNN 实现和 autocast 配合曾经有过不少问题，早期版本直接报 `CUDNN_STATUS_BAD_PARAM`，PyTorch 侧修复过多次，但至今仍能看到 fp16 下 LSTM 出现 NaN 的报告，原因大致是中间量 `W·x + U·h + b` 超出 fp32 上限时并行归约产生了 `Inf - Inf`。稳妥做法是 LSTM 层强制 fp32，或者干脆用 CPU 路径。

## 回到起点

三根轴这个框架真正的用处，不是给历史排座次，而是让今天的选择变得可解释。LSTM 的强项是梯度路径，弱项是状态容量和训练并行；Transformer 反过来，强项是路径长度和平行度，弱项是推理状态随长度涨；xLSTM、Mamba、RWKV 各自拿走了一根轴上的最优解，同时把另外两根轴的短板暴露出来。

所以"LSTM 死了没有"这个问题本身是错的。死掉的是那个把三根轴全押在同一种结构上的方案，活下来的是把三根轴拆开重新组合的自由。今天站在这三根轴上做选择，才是这篇演进史能给的东西。
