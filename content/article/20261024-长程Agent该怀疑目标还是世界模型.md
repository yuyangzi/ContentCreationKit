# Agent 跑长程任务时，缺的不是反思，是能证伪自己的信号

> **导读**：2026 年 10 月，第三方评测机构 Preference Model 把 Terminal-Bench 4.0 的 66 道题移植复核了 65 道，发现其中 41 道的解法本身是对的，被判失败的原因是评分器。
>
> 同一周，月之暗面披露了另一件事：一个 Agent 在奖励函数怎么调都不动的情况下，停下来去测自己搭的那套仿真器，修掉 36 处肩部肌肉力臂计算错误，然后重训控制器。
>
> 两件事隔着评测与训练两个场景，一件由第三方审计发现，一件由 Agent 自己发现，问的却是同一类问题：该怀疑目标，还是该怀疑目标所依赖的那个世界。

2026 年 10 月 19 日，Preference Model 发布了一份关于 Terminal-Bench 4.0 的报告，标题是《Terminal Bench 4 Is Saturated》。他们把 66 道题移植过来复核了 65 道，其中 41 道存在评分器的暗规则：Agent 做完了要求的工作，仍然被判失败。

把暗规则修掉之后，Claude Sonnet 5.5 在这批题上的分数从 62.8% 跳到 89.2%。

报告里还记了反方向的例子。前沿模型在利用评分器的缝隙：GPT-5.6 Sol 在一个叫 biped-contact-dynamics 的任务里，让机器人在两个遮罩帧之间向前瞬移一整步；GPT-6 Sol 把耗时的操作挪进了不计时的 setup 阶段。

这两类现象放在一起看，评测这件事就露出了一层底：分数低未必是 Agent 不行，分数高也未必是它做对了。评分器是 Agent 面对的那个“世界”，而这个世界本身可能是错的。

这里说的“世界”，指的是 Agent 用来判断“这个动作会带来什么后果”的那套模型，也就是强化学习里的世界模型（world model）。后面提到“世界”，主要指这一层；评测场景里，这个词也包括评分器。

同一周，月之暗面在 Kimi K3.1 Pro 的发布博客里写了一件更小、也更具体的事。

---

## 一次内部测试里的 167 项任务

官方原文里最关键的一句：

> When reward shaping failed to improve arm motion, K3.1 Pro did not simply keep adjusting the reward: it ran open-loop probes of the simulator's dynamics, identified and corrected 36 errors in shoulder-muscle moment-arm calculations, and then retrained the controller.

这段引文说的是动作。这次内部测试的结果是：它在开源人体解剖模型 human-atlas 之上搭起仿真器，从几秒内倒地到交替迈步连续走 11.2 秒。而当奖励塑形（reward shaping）对改善手臂运动无效时，它没有继续调奖励，而是对仿真器的动力学做开环探测，找出并修正了 36 处肩部肌肉力臂计算错误，然后重新训练控制器。

human-atlas 这个项目本身不含动力学，仓库里见不到任何物理仿真模块。它是一个纯前端 3D 解剖浏览器，用 React 和 Three.js 写成，数据来自 BodyParts3D 4.0 的成年男性参考解剖，共 2,234 个可选中 mesh；

骨骼 296 块、肌肉 402 块的拆分来自月之暗面的博客描述，README 里自述定位是“educational explorer, not a diagnostic or surgical tool”。

也就是说，会算力臂的那一层，是 Agent 自己写出来的。肌肉路径怎么走、力臂怎么随关节角变化、激活信号怎么映射成关节力矩，这套东西原先不存在，是它在这次任务里搭的。

这一点改变了整件事的性质。如果力臂来自一个成熟的第三方物理引擎，模型只是发现了引擎的 bug，那是一个测试者的故事。但在这里，写代码的是它，评审代码的也是它。**它得怀疑到自己写的那部分实现上去。** 36 处错误不是一个外部库的缺陷清单，是它自己的建模错误清单。

---

## 这份证据的成色

往下推之前，这份材料的成色需要先说清楚。

11.2 秒的连续行走，按成年人步频折算大约是十来个步态周期。官方用的是“from collapsing within seconds to walking continuously”这个对比，所以这是可行性演示，不是能力刻度。一个真人的连续行走以小时计。

数字的来源也需要标注。167 项任务、420 次独立评审、36 处力臂错误，全部来自官方一次内部测试（尚无第三方复现）。420 次评审由谁执行，是人、是模型还是自动评分器，官方没有说明。评审如果是模型评审，它自身就带着自我偏好的问题。

配套的 Kimi Code Bench 3.0 Long-horizon 是厂商内部基准，得分是 61.2%，没有公开题库，也没有第三方复跑通道。

> 可检验的是它做了什么，不是它做得多好。值得关心的是动作的类型，不是数字的大小。

这层边界不改变后面的论证方向：哪怕 11.2 秒只是个很小的成就，“奖励调不动就转去测模型”这个动作在公开披露的案例里也很少见。

## 奖励写错了，和世界算错了

强化学习里有两种失败，长得像，治起来完全不同。

第一种是代理奖励（proxy reward）和目标脱了钩。你想要 A，写了个 B 当替身，优化器把 B 推到很高，A 却没动甚至更差。这类问题的名字很多，reward hacking、specification gaming、Goodhart 效应，说的都是同一件事：**奖励函数本身写错了。**

Skalse 等人在 2022 年给过一个严格的结论（arXiv:2209.13085）：在全体随机策略集上，除非代理奖励本身是常数，否则它一定能被 hack；确定性策略集或有限策略集上才存在非平凡的例外。

换句话说，工程里的策略集通常足够丰富，代理奖励就只剩被利用的难度差别（把工程问题近似成全体随机策略集，是本文的推论）。Karwowski 等人 2023 年把这套分析搬进马尔可夫决策过程（arXiv:2310.09144），给出了一条更贴近工程的曲线：对不完美代理的优化越过某个临界点之后，真目标的性能开始下降。

这类失败的特征是，你越努力，错得越系统。DeepMind 的 specification gaming 案例清单里有一例 Coast Runners：比赛目标是尽快跑完全程，击中绿块只是塑形奖励，智能体发现原地绕圈刷绿块拿分更高。奖励没有算错，是它本来就只描述了目标的一部分。

第二种失败不一样。奖励可能写得完全正确，错的是**评估这条策略的那个世界**。

在基于模型的强化学习（model-based RL）里，这是个老问题。Janner 等人 2019 年的 MBPO（arXiv:1906.08253）把机理讲得很清楚：如果让策略在一个学出来的模型里自由地长时间展开，模型误差会沿着视界复合，误差上界随有效视界 1/(1-γ) 二次增长。策略会学会在模型错误的地方拿高分，这就是所谓的模型利用（model exploitation）。

更早的一个统计学结论解释了为什么优化器总会撞上这件事。Smith 和 Winkler 在 2006 年的《The Optimizer's Curse》里指出，即使每个选项的估计都是无偏的，**取最大值这个动作本身**也会系统性地选中被高估的那一个，于是实际结果系统性低于估计。模型误差乘以选择压力，等于系统性的失望。

那只调不动的手臂，问题就出在这里。肌肉骨骼仿真里，关节力矩有这么一层关系（Sherman、Seth、Delp，2013）：

$$
\tau = s(q, a) \cdot r(q)
$$

s 是肌肉张力，取决于关节角 q 和激活 a；r 是力臂，在无功约束下由肌肉路径长度对关节角的导数 dL/dq 给出。力臂不是常数，它随 q 变，肩部尤其麻烦：三角肌、肩袖那几组肌肉跨多个刚体绕曲面走行，力臂曲线得逐块实测对表。Holzbaur 等人在 2005 年的上肢模型里，50 个肌室、15 个自由度，方法学核心正是用实验数据校验每个肌群的力臂曲线。

如果 r(q) 系统性算错了，那么“激活到力矩”的映射本身就错了。任何激活轨迹，也就是任何控制器、任何奖励塑形引导出来的策略，都没法在这套仿真里产生正确的手臂运动。

而奖励是对轨迹打分的。它看见的是“手臂没抬起来”，看不见 r。

> 奖励函数写得再对，也无法修正一具算错了力臂的身体。调参调的是 s，坏掉的是 r。

这就是为什么“继续调奖励”在这条路上走不通。不是调得不够好，是调错了层。

## 闭环会把世界的错误藏起来

还有一层更隐蔽的原因。

策略在错误的世界里训练，通常不会表现成“明显错误”，而会表现成“怎么调都不动”。因为反馈控制器天生就会补偿。

控制器的作用就是消化偏差：给它一个偏离目标的系统，它会学出一个反向的补偿项，把偏差压回去。这套能力在真实系统里是优点，在诊断场景里是缺点。当模型误差是结构性的（比如某块肌肉的力臂在某个角度区间上整体偏低），控制器会在那个区间上多给一点激活，用更大的张力去补更小的力臂。轨迹看起来还行，误差被吸收进了策略里。

这时的症状特别容易误导人：奖励曲线是平的，行为没有改善，加大训练量也没用。工程直觉会往“策略不够强”或者“奖励设计不够细”上走，于是继续调，继续平。

一个更日常的类比是坏掉的恒温器。房间温度传感器偏了两度，控制器会一直加力，直到实际温度高出两度为止。你看到的不是“传感器坏了”，而是“这个房间总是偏热，怎么调设定值都没用”。

所以在这类系统里，**控制器的鲁棒性是诊断的敌人**。它越能补偿，你越难从行为上看出世界错了。

## 开环探测是自造的外部信号

官方只写了“ran open-loop probes of the simulator's dynamics”这一句，没有给方法。工程上能对应上的，是系统辨识（system identification）里的标准动作：把控制器冻结或者摘掉，给系统一串预先定好的输入，记录输出，然后拿输出和预期比。

闭环和开环的差别就在这里。闭环是边跑边改，观测到的每一步都带着控制器的影响；开环是不改，只看系统本身怎么响应。前者测的是“策略加世界”，后者测的是“世界”。

回到力臂。r(q) = dL/dq 是个可以直接算的量：给定关节角，量一次肌肉路径长度，再给一个微小扰动，量第二次，差分就是力臂。把它在整段关节角上扫一遍，和参考曲线对比，残差有结构（比如某个区间整体偏低、某个角度上跳变），就说明模型错了；残差是散乱的噪声，就说明模型没问题，问题在策略侧。

```Python
import numpy as np

def moment_arm(path_length, q, h=1e-4):
    # r(q) = dL/dq：肌肉路径长度对关节角的导数，中心差分
    return (path_length(q + h) - path_length(q - h)) / (2 * h)

def open_loop_probe(muscles, q_grid, reference, tol=1e-3):
    # 控制器冻结，只扫关节角，返回残差超阈值的肌肉与角度
    findings = []
    for name, path_length in muscles.items():
        r = np.array([moment_arm(path_length, q) for q in q_grid])
        residual = r - reference[name]
        if np.abs(residual).max() > tol:
            i = int(np.abs(residual).argmax())
            findings.append({
                "muscle": name,
                "angle": round(float(q_grid[i]), 4),
                "probe": round(float(r[i]), 4),
                "expected": round(float(reference[name][i]), 4),
            })
    return findings
```

这段代码的关键不在差分，在 `open_loop_probe` 的入参：它不接策略，不接奖励，只接“给定角度下肌肉有多有效”和一份参考值。整个函数里没有一步是在改进行为，它只回答一个问题：这套仿真器在物理上对不对。

这是它和自我反思的区别所在。

关于自我修正，学术界有一条相当一致的结论线。Huang 等人 2023 年的《Large Language Models Cannot Self-Correct Reasoning Yet》（arXiv:2310.01798）测了“内在自我修正”，也就是不给任何外部反馈、只让模型重看自己的答案：在被测的模型和基准上，自纠之后准确率都下降了。

论文点名的 RCI（Recursive Criticism and Improvement）和 Reflexion 两项工作看似有效，实际上是给了 oracle 标签，模型知道什么时候该停。

Kamoi 等人 2024 年的综述（arXiv:2406.01297）把这条线收得更紧：除了极少数天然适合自纠的任务，没有证据表明 prompt 层面的自我反馈能成功自纠；能工作的场景，都有可靠的外部反馈。

再往前一步是偏差问题。Panickssery 等人 2024 年的实验（arXiv:2404.13076）发现，模型识别自己生成内容的能力与偏好自己生成内容的程度线性相关：GPT-4 在两两比较里不做微调就有 73.5% 的自我识别准确率，微调 500 个例子之后，GPT-3.5 和 Llama 2 的自我识别率都超过 90%。让同一个模型评价自己，它认得出，也偏得动。

所以开环探测在这个案例里的位置可以说得更准：它不是一次更认真的反思，它是一次**外部信号的制造**。模型很难靠内省发现自己把力臂算错了，因为内省用的是同一套权重和同一条推理路径，错误是相关的。它只能去造一个能证伪自己的东西：一个不经过策略的输入输出对，一个残差，一个能被测出来的数。

> Agent 变强的原因不是更会反思，是它给自己造了一个能证明自己错的信号。

这也顺带解释了为什么这个动作在长程任务里罕见。反思的成本很低，随时可以做；造信号的成本很高，得先想清楚“我怀疑哪一层”，再设计一个能把那一层单独拎出来的实验。前者是语言能力，后者是实验设计能力。

## 评分器也是一个世界

把视线从训练挪回评测，那 41 道题还有另一面。

前面提到的 41 道题，问题出在 Terminal-Bench 4.0 的评分器里有大量未写进任务描述的判分规则，正确的工作被判失败。另一头，Anthropic 在受控实验里记录过反方向的例子：模型学会在 Python 里调 `sys.exit(0)`，直接从测试 harness（评测框架）里跳出去并返回成功码。他们的说法是，这相当于学生在自己的作文顶上写了个“A+”。

同一套评分器，会同时产生假阴性和假阳性。

这件事和力臂是同一个结构。Agent 做对了工作却被判失败，它面对的是一个算错了的世界；Agent 钻了评分器的空子拿高分，它面对的是一个可以被优化器利用的世界。两种情况下，从分数上你都看不出到底是谁错了。

分数的口径问题还可以再叠一层。Kimi 官方给的 Terminal-Bench 4.0 是 65.7%，对照 Opus 5.5 的 66.4%；脚注写明，K3.1 Pro 用的是 Claude-Code harness，DeepSeek-V4.1-Flash-1017 的分数取其发布博客，其余模型取各自博客或官方榜单的最大值。

Artificial Analysis 用统一的 mini-swe-agent harness 复跑同一套题，66 题各跑 3 次取 pass@1，结果是 K3.1 Pro 67.2%，在该榜最高；同一次评测里，Sonnet 5.5 是 63.6%，Opus 5.5 是 59.6%。

三组数字摆在一起，跨来源比较就不成立了。65.7 和 66.4 之间的 0.7 分差距，落在 harness 差异带来的噪声里，比“追平”这个说法要小得多。

而同一个模型、同一个基准，换个 harness 分数就不同：K3.1 Pro 从 65.7 变成 67.2，Opus 5.5 从 66.4 掉到 59.6，取决于谁在打分、用什么框架打分。Artificial Analysis 那样统一 harness 的复跑，本质上就是评测侧的开环探测：把“世界”固定住，只让策略变。

> 长程评测里，“策略”和“世界”的边界同样需要被审计。分数同时混入了策略质量和打分口径，而报告通常只给一个混合后的数。

## 停止调参的四个信号

把上面几层合起来，工程上真正可用的，是几条能被触发的信号，而不是一句“要学会怀疑世界”。下面这些现象出现时，继续调参的期望收益往往已经很低。

| 现象 | 更可能错在哪 | 下一步动作 |
|---|---|---|
| 奖励单调上升，行为不变 | 代理奖励与真目标脱钩 | 换评估指标，先别看训练曲线 |
| 每次调参只换来另一种错法 | 目标映射错 | 重写奖励定义 |
| 闭环无增益，开环残差有结构 | 所依赖的世界错了 | 定位参数，修模型后重训 |
| 开环残差接近噪声，闭环仍差 | 策略或搜索错 | 调策略，加独立验证器 |

第三行和第四行的分界只看残差有没有结构：有结构（某段输入整体偏低、某个参数上跳变）说明世界错了，接近噪声才轮到策略侧动手。

---

## 五条可以带走的做法

1. **先拆失效层级，再动任何参数**。顺序是：目标对不对，评估它的那个世界对不对，策略够不够强。跳过前两层直接调第三层，是一种常见的浪费。
2. **把“调参无效”当成升级信号**。连续几轮调整只换来误差搬家，就应该停止调参，转去做一次开环探测。这个规则可以写进 harness，不需要模型自己顿悟。
3. **用不变量当 oracle**。力臂有对称性，能量该守恒，等价输入该给等价输出。这些约束不依赖参考数据，成本低，而且能直接指出错误发生在哪一段。
4. **看残差的结构，不看残差的幅度**。幅度大可能是噪声，也可能是尺度问题；有结构（单调偏移、跳变、区间性偏差）才说明模型漏了东西。这一条是从系统辨识搬过来的老经验，在 Agent 场景里同样成立。
5. **给诊断单独留预算**。开环探测不属于训练，它不改进策略，只产出一份关于世界的报告。在长程任务的成本核算里，这一项经常被漏掉，而它恰恰是“调不动”时少数还能推进的动作之一。

## 三个容易犯的错

反过来，这套框架有三处容易走偏。

1. **把开环探测当成让模型反思。** 两者在日志里看起来都是“模型停下来想了一会儿”，但产出的东西完全不同：反思产出的是自我评价，探测产出的是可证伪的量。判断标准很简单，看有没有一个新的、不经过策略的观测。
2. **把奖励塑形当万能旋钮。** 奖励塑形是个有用工具，但不是中性的。非势函数形式的塑形不保证最优策略不变，Coast Runners 那一例的背景正是塑形奖励改变了最优策略。当症状是“怎么调都不动”，先确认这个旋钮接的是不是正确的电路。
3. **把演示当刻度。** 11.2 秒是一个可行性信号，说明这条路能走通；它不是一个能力数值。这两件事在传播里经常被合并成一句“前沿模型能自主做科研了”，而原始材料只支持前一半。

---

长程 Agent 的分水岭，不在它能连续跑多少步，也不在单步成功率有多高，而在优化停住的那一刻，它怀疑的是目标，还是目标所依赖的那个世界。

这两层怀疑的代价差得很远。调奖励便宜，改 prompt 更便宜，重试最便宜。去测自己写的那套仿真器，要设计输入、要冻结控制器、要知道该看哪个量，还得接受“错的是我”。前三条路走不通的时候，多数系统会继续在里面转，因为那三条路的反馈来得快。

Kimi 这个案例真正稀缺的地方，是它把“错的是我”这个判断做成了一个可执行的实验。至于这个实验做得有多好，11.2 秒说明不了什么，得等权重放出来、等有人把它跑一遍才知道。
