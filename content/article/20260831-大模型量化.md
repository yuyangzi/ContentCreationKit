# 从 FP16 到 1.58-bit：大模型量化的成本、甜点与极限

> **导读**：大模型推理的成本瓶颈不在计算，而在显存。量化——把模型权重从 FP16 压到 INT4 甚至更低——是目前最直接的降本手段。但为什么 4-bit 比 8-bit 难做？GPTQ 和 AWQ 的本质区别是什么？1-bit 模型是未来还是噱头？这篇文章从显存墙出发，梳理量化的核心原理、主流方案、推理生态和最新前沿。

2026 年 8 月，阿里开源 Qwen3.8-27B，模型权重大小约为 56GB（Hugging Face checkpoint 实测 55.6GB）。一块 RTX 4090 只有 24GB 显存，直接跑，模型无法完全卸载到显存。INT4 量化后，权重降到约 16GB，加上 KV cache 和运行时开销，4090 不仅能跑，还能跑得很快。

这不是魔法，是量化（Quantization）。

## 推理的瓶颈不是算力，是显存

对于自回归生成的语言模型，推理慢的原因不是 GPU 算得不够快，而是显存带宽不够。

生成每个 token 时，GPU 需要把模型的所有权重从显存读入计算单元。以一个 7B 模型为例，FP16 下权重占 14GB。RTX 4090 的显存带宽约 1 TB/s（官方规格 1008 GB/s），读完 14GB 需要约 14 毫秒——这意味着即使计算单元全速运转，每个 token 的理论下限也被带宽卡在了 14 毫秒左右。

> **量化的本质不是让计算更快，而是让需要搬运的数据变少。** 把 FP16 压到 INT4，权重体积直接降到原来的 1/4，每个 token 的生成时间也相应缩短。

这就是为什么量化是目前 LLM 推理优化中性价比最高的手段——不改架构、不换硬件，直接把模型变小。

## 量化到底在做什么

量化的核心操作是把浮点数映射到整数。公式看起来很简单：

```
Q = round(x / scale) + zero_point
```

其中 `scale` 是缩放因子，`zero_point` 是零点偏移。反量化时，用 `x_hat = (Q - zero_point) * scale` 把整数还原为浮点数。

这个过程中有两类误差在打架。**取整误差**来自 `round` 操作（把 3.7 变成 4，差了 0.3）。**裁剪误差**来自数值超出量化范围——如果 INT8 的范围是 [-128, 127]，而某个激活值是 200，它就会被截断成 127，信息直接丢失。

这两类误差的权衡，决定了量化的难度。

FP16 的表示范围大约是 ±65504，INT8 只有 [-128, 127]。看起来压缩比很大，但问题在于：权重可以逐层统计范围，然后选一个合适的 scale；激活值却不同——它的范围随输入变化，而且存在离群值（outlier）。

SmoothQuant 论文里有一个关键发现：在 Transformer 的激活中，离群值幅度可以达到常态值的 100 倍左右，而且这些离群值固定在少数几个通道上，跨 token 持续存在。如果用 per-tensor 量化（整个矩阵共享一个 scale），离群值会把 scale 撑大，导致常态值只能用到 2-3 个量化级——信息几乎丢光了。

这就是为什么激活量化比权重量化难得多。目前主流的 4-bit 方案（GPTQ、AWQ）都是 W4A16——权重压到 4-bit，激活保持 FP16。只解决搬运问题，不解决激活的量化问题。

## 粒度：量化的精度杠杆

量化粒度决定了 scale 的作用范围。粒度越细，每个 scale 覆盖的数值范围越窄，量化误差越小，但存储 scale 本身的开销越大。

- **Per-tensor**：整个权重矩阵共享一个 scale。开销最小，但精度最差——一个离群值就能毁掉整个矩阵的量化质量。
- **Per-channel**：每个输出通道一个 scale。权重量化的常用选择，精度和开销平衡得不错。
- **Group-wise**：每 128 个元素共享一个 scale。GPTQ 和 AWQ 的默认配置，在 4-bit 下几乎不损失精度。

Group-wise 是目前 4-bit 量化的甜点：Group size=128 时，128 个 4-bit 权重只需额外存一个 16-bit 的 scale，存储开销不到 5%，可以忽略不计，而每个 group 内的数值范围被约束得更紧，量化误差大幅下降。

## GPTQ 和 AWQ：两种思路，一个目标

GPTQ 和 AWQ 是目前最主流的两种 4-bit 量化方案，目标都是 W4A16，但思路截然不同。

**GPTQ 的核心是"补偿"**。它基于一个观察：量化一个权重产生的误差，可以通过调整尚未量化的权重来抵消。具体做法是利用 Hessian 矩阵（损失函数对权重的二阶导数）衡量每个权重对最终输出的影响，逐列量化，每量化一列就立刻把它的误差传播给未量化的列共同补偿，使整体输出误差保持近似不变。得益于这种"延迟更新"设计，量化顺序对最终精度的影响其实很小，任意顺序即可。

这个过程是 one-shot 的：只需要一批校准数据（通常是 C4 数据集的 128 个片段），跑一遍前向传播，就能完成整个模型的量化。不需要训练，不需要反向传播。

**AWQ 的核心是"保护"**。它发现权重不是同等重要的。大约 0.1% 到 1% 的权重通道，因为对应的激活值幅度特别大，对模型输出的影响远超其他通道。这些"显著通道"一旦被量化，精度损失会很大。

AWQ 的做法是：在量化之前，先统计激活分布找到显著通道，然后把这些通道的权重乘以一个缩放因子（scale up），同时把对应的激活值除以同一个因子。数学上，这是等价变换——输出不变。但量化时，这些被放大的权重在 4-bit 表示中占了更多级数，相对误差变小了。

> **GPTQ 是"先量化再补偿"，AWQ 是"先保护再量化"。** 前者依赖二阶信息做全局优化，后者依赖激活统计做局部保护。

两种方案在 4-bit 下的精度差距不大，但 AWQ 有一个优势：跨域泛化更好。当校准数据和评测数据分布不同时，AWQ 的困惑度上升约 0.5-0.6，而 GPTQ 上升 2.3-4.9（AWQ 论文，OPT-6.7B、INT3 实验）。原因是 GPTQ 的补偿机制对校准数据有一定过拟合，而 AWQ 的保护策略更鲁棒。

HQQ 则干脆绕开了校准数据这一步：用半二次分裂做鲁棒优化，自动求解每组的 scale 和零点，量化 Llama-2-70B 只需几分钟，精度与依赖校准数据的方案接近（HQQ 官方博客，2023）。

## SmoothQuant：让激活也低比特

GPTQ 和 AWQ 只量化了权重，激活仍然是 FP16。如果想进一步压缩，就得对激活下手。

SmoothQuant 的切入点是：激活的离群值问题，本质上是"激活和权重在量化难度上的不平衡"。激活有离群值，难量化；权重分布均匀，好量化。解法是让两者互相帮一把。

具体做法是：对每个通道，计算一个平滑因子 `s = max(|X|)^α / max(|W|)^(1-α)`，然后把激活除以 `s`、权重乘以 `s`。数学上，输出完全不变。但激活的离群值被压下去了，权重的分布变"粗糙"了——而权重本来就耐糙。

α 是迁移强度。α=0.5 时，难度均摊到两边，大多数模型在这个点上达到平衡。少数模型（如 GLM-130B）的激活离群特别强，需要 α=0.75 把更多难度推给权重。

SmoothQuant 让 W8A8（权重 8-bit + 激活 8-bit）成为可能，论文报告在 OPT、BLOOM 等模型上实现了约 1.56 倍加速和 2 倍显存节省。

## 推理生态：格式、框架和硬件

量化方案是算法，真正让它跑起来的是推理生态。

**GGUF 格式**是 llama.cpp 生态的容器，也是目前本地部署最主流的格式。它的核心是 K-quant 家族——以 256 个元素为一个"超级块"，内部再分 16 或 32 元素的子块，每个子块有独立的 scale。不同张量类型分配不同比特：Q4_K_M 约 4.8 bpw（bit per weight），Q6_K 是 6.56 bpw，Q8_0 是 8.5 bpw。后缀 `_S/_M/_L` 表示混合精度策略（`_M` 会把注意力中的 `attn_v` 和 FFN 中的 `ffn_down` 等敏感层提升到更高精度）。

后来出现的 **IQ-quants** 在 K-quant 基础上引入了重要性矩阵（imatrix）——用校准数据计算每个权重对输出的重要性，量化时按重要性加权重建。IQ4_XS 在 4.25 bpw 下就能接近 Q4_K_M（约 4.8 bpw）的质量，代价是对 imatrix 的质量更敏感。

**bitsandbytes** 走的是另一条路。LLM.int8() 把权重和激活都量化为 INT8，但对离群值所在的维度保留 FP16 计算——大约 0.1% 的维度用 FP16，99.9% 用 INT8，内存减半且基本无损。NF4（NormalFloat 4）则是为 QLoRA 设计的：针对权重服从正态分布的特点，把量化级不均匀分配，在均值附近分得更密、两端分得更疏，对正态分布权重而言是信息论最优的 4-bit 表示。

硬件层面，**FP8 是分水岭**。Ada Lovelace（RTX 40 系）和 Hopper（H100）有原生 FP8 Tensor Core，8-bit 权重可以配合低比特激活直接加速矩阵乘法。Ampere（A100、RTX 30 系）没有原生 FP8，FP8 checkpoint 只能以 W8A16 运行——权重 8-bit 存储省显存，计算时反量化回 FP16，不加速。Blackwell（B200、RTX 50 系）进一步支持 FP4，B200 还额外原生支持 MXFP8 块缩放格式，把低精度推理的硬件基础又往前推了一步。

## 1-bit 的诱惑

2024 年，微软发表了 BitNet b1.58，从三值 {-1, 0, +1} 的视角重新定义了 1-bit LLM。三值有 3 个状态，每个权重的信息量是 log₂(3) ≈ 1.585 bit，所以叫 1.58-bit。

BitNet b1.58 的核心论点是：在同等模型规模和训练 token 数下，1.58-bit 权重的困惑度和下游任务表现可以匹配 FP16（匹配结论在 3B 规模上得到验证，更大规模尚无公开验证）。这不是推理时的后训练量化，而是从头以 1.58-bit 训练——相当于重新设计了训练算法来适配三值表示。

2025 年的 BitNet v2 更进一步，引入了 H-BitLinear：在量化之前做在线 Hadamard 变换，把尖锐的激活分布旋转成类高斯分布，从而抑制离群值。这让 1-bit 模型首次支持原生 4-bit 激活——不再需要 8-bit 激活来兜底。

但 1-bit 目前有一个根本局限：它需要从头训练，不能直接量化现有的 FP16 模型。从头训练意味着重新投入预训练量级的算力和数据，而 GPTQ、AWQ 只需要 128 个校准片段跑一遍前向。BitDistill 尝试用蒸馏把现有 LLM 压缩为 1.58-bit，但仍然是特定任务的微调，不是通用方案。

> **1-bit 不是量化的终点，而是一条平行的路线。** 它用专用训练换极致压缩，适合从头构建的端侧模型；后训练量化（GPTQ、AWQ）则是现有模型的"近无损瘦身"，两者解决的是不同的问题。

## 前沿：稀疏、码本和旋转

2025-2026 年的量化研究有几个明显趋势。

**稀疏 + 量化**。Sparse-BitNet 发现 1.58-bit 三值权重天然适配半结构化 N:M 稀疏——三值中的"0"本身就是稀疏，两者叠加可以进一步压缩而不损失精度。SharQ 则把激活稀疏性和 FP4 量化结合，解决激活中 input-dependent 的离群值主导 FP4 block scale 的问题。

**码本量化**。QuIP# 用 E8 格（8 维空间中最优的球体填充）作为码本，配合随机 Hadamard 旋转，在 2-4 bit 下达到了当时的 SOTA。AQLM 走的是加法量化路线：用多个小码本的码字叠加来表示权重，是 2-bit 级极限压缩的代表方案。走另一条路的 CubicQuant 则不做向量联合编码，而是把非均匀量化级参数化，覆盖 1-8 bit 全范围且保持 GPU 高效执行。Leech Lattice VQ 则从信息论角度证明：标量量化有根本极限，向量量化（对参数块联合编码）可以突破这个极限。

**旋转消除离群值**。QuaRot、SpinQuant、FlatQuant 等一系列工作用不同的旋转策略（随机 Hadamard、学习旋转、基于平坦度的旋转）把激活和权重的分布"转"得更平滑，从而让 4-bit 端到端（权重 + 激活 + KV Cache）量化成为可能。

**混合精度自动搜索**。KVTuner 用敏感度分析做逐层 KV cache 的混合精度分配，无需训练和反向传播，实现近无损的缓存压缩。

## 量化的边界在哪

量化是有极限的。

从信息论角度看，一个 FP16 参数占用 16 bit 存储，但它携带的真实信息量（分布的熵）通常远小于 16 bit——模型的参数本身就有大量冗余，相当一部分权重可以被剪掉而对输出影响有限。只要权重真正携带的信息能被 4 bit 装下，压到 4 bit 就几乎没有损失。量化本质上是在"用更少的存储位，逼近参数的真实信息量"。

目前 4-bit 是工程甜点：在通用文本任务上精度损失可忽略，显存和速度收益明显；但在代码生成、数学推理这类任务上仍有可感知的退化，模型越小越明显。3-bit 已经需要更复杂的方案（码本、蒸馏）来维持质量。2-bit 在特定方案下可行，但退化明显。1-bit 需要从头训练，是另一条技术路线。

> **量化的极限由冗余度和算法共同划定：模型的冗余度决定信息论意义上的最终下限，算法决定能逼近这个下限到什么程度。** 标量量化有一道高于最终下限的"假天花板"，Leech Lattice 证明向量量化能突破它、把压缩极限往下压，这本身就是算法在起作用。模型如果通过架构和训练变得更"紧凑"，冗余度下降、最终下限抬高，反过来又逼着码本、旋转这些方法继续往前走——冗余度决定极限在哪里，算法决定极限能推到多远。

对于普通开发者来说，今天最实用的选择有三个：

1. 用 GGUF 格式的 Q4_K_M 做本地推理
2. 用 vLLM 的 AWQ/GPTQ 做服务部署
3. 关注 FP8 在 Ada/Hopper 硬件上的原生支持

至于 1-bit 和稀疏量化，它们可能在端侧等特定场景率先落地，也可能长期停留在论文里。
