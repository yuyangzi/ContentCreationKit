# MoE 路由：均衡、专业化与因果性的不可能三角

> **导读**：MoE（Mixture of Experts）的核心思想很简单——让不同的专家处理不同的任务。但真正运行起来，一个根本性的矛盾浮出水面：你既希望每个专家都成为某个领域的「专才」，又必须保证每个专家都分到差不多多的活，在自回归模型里还不能让路由决策「偷看」未来。本文梳理 2017 到 2025 年，MoE 路由在均衡、专业化与因果性三重张力下的演进。

2024 年 12 月，DeepSeek-V3 发布，671B 总参数但每个 token 只激活 37B。这串数字背后是一套精巧的路由机制——路由器（router）决定每个 token 该交给 256 个专家中的哪 8 个来处理。听起来像是一个简单的分配问题，但过去七年里，它催生了一个完整的研究领域。

---

## 路由器在做什么

想象一个大型医院的挂号系统。每个病人（token）到来时，系统根据病情分配到一个专科医生（专家）那里。理想情况下，每个医生都在自己的专长领域里工作，病人得到最专业的治疗。但现实是，如果挂号系统不够聪明，心内科可能排起长队，而皮肤科整天闲着——后者浪费资源，前者病人流失。

MoE 的路由器干的就是这个挂号的事。每个 token 进入一层 Transformer 时，路由器计算它与所有专家的「匹配度」，然后选出最合适的 K 个专家来处理。未被选中的专家完全不参与计算，这就是 MoE 能用 671B 参数实现 37B 计算量的原因。

但问题在于：**如果路由器总是把相似的 token 派给同样的专家，少数专家会过载，多数专家会饿死。**

这个现象有个正式的名字：负载不均衡（load imbalance）。它不只是效率问题。过载的专家会溢出（token 被直接丢弃），饿死的专家学不到东西，整个模型的容量被浪费。

---

## 一个自强化陷阱

2017 年，Shazeer 等人在 MoE 的开创性论文里观察到一个现象：负载不均衡是「自强化」的。被偏爱的专家训练得更快，因此在下一轮被路由器选中的概率更高，然后训练得更快……正反馈一旦形成，少数专家垄断所有 token，其余专家沦为摆设。就像医院只看治愈率挂号，最后整个医院只剩一个科室在运转。

打破这个循环的第一个办法很直觉：加一个惩罚项。

---

## 辅助损失：用「行政命令」干预市场

这种惩罚项在 Shazeer 2017 年的论文里就已出现雏形，GShard（2020）沿用了类似设计，把它做成后来通行标准形式的是 Switch Transformer（2021）的辅助损失函数（auxiliary loss）。核心思路是：在训练时额外加一项惩罚，如果某些专家被分到的 token 太多，就给路由器扣分。

这个惩罚项的设计很巧妙。它包含两个向量：一个是每个专家实际收到的 token 比例（离散的，不可导），另一个是路由器给每个专家的平均概率（连续的，可导）。两者相乘后求和——当所有专家被均匀分配时，这个值最小。

效果立竿见影。Switch Transformer 在同等算力下取得最多 7 倍的预训练加速。但代价也随之而来。

辅助损失本质上是在路由器的优化目标里塞进了一个「行政命令」。路由器现在有两个任务：一是把 token 派给最合适的专家（主损失），二是保证大家均匀分配（辅助损失）。这两个目标天然冲突——最合适的专家就那么几个，你非要均匀分配，就等于逼着路由器把一些 token 派给不那么合适的专家。

这就像医院管理层规定「每个医生每天必须看同样多的病人」——公平是公平了，但复杂病例可能被迫分给了全科医生而非专科医生。

更麻烦的是，辅助损失的超参数 α 是个双刃剑。α 太小，路由坍缩照旧；α 太大，主损失被压制，模型的语言建模能力直接掉点。Switch 论文扫描了从 10⁻¹ 到 10⁻⁵ 的范围，最终选了 10⁻²——一个「刚刚好」的值。但「刚刚好」只对当前模型、当前数据、当前规模成立。

---

## Z-Loss：稳定性的暗战

如果说辅助损失解决的是「公平」问题，那 Router Z-Loss 解决的是另一个隐藏更深的问题：数值稳定性。

ST-MoE（2022）发现，MoE 模型比稠密模型更容易训练发散。原因出在路由器的 softmax 上。训练过程中，路由器的 logit（softmax 的输入分数）会逐渐漂移到很大的值，导致 softmax 输出趋近 one-hot——路由器变得「武断」，几乎把所有 token 都塞给同一个专家。

Z-Loss 的做法是惩罚 logit 的平方和，把它们拉回合理区间。这个技巧看起来不起眼，但实验表明：加了 z-loss 后，原本 6 次训练只有 4 次稳定的基线，变成了 3 次全部稳定。而用收紧权重更新裁剪（update clipping）来硬压不稳定，虽然 3 次运行也能全部稳定，但模型质量直接崩了——负对数困惑度从基线的 -1.755 恶化到 -4.206（对应困惑度约从 5.8 飙升到 67）。相比之下，z-loss 自身的质量分是 -1.741，甚至略优于基线。

**稳定性和质量很难靠粗暴裁剪换取。** 这是 ST-MoE 最重要的经验之一。

---

## Expert Choice：反转视角，让专家选 token

2022 年，Zhou 等人提出了一个大胆的设想：与其让 token 选专家，不如让专家选 token。

具体做法是：每个专家都有一个固定的「接诊名额」，路由器计算所有 token 对所有专家的亲和度，然后每个专家从候诊室里挑与自己最匹配的 token。

这个方案在机制上解决了负载不均衡——每个专家的接诊量是固定的，不存在溢出，也不需要辅助损失。而且，重要的 token 可以被多个专家同时处理，不重要的 token 可能只被一个专家处理，计算资源按重要性分配。

实验结果同样扎实：8B 激活参数（总参数 143B；论文架构表里实测激活为 9.8B）、64 个专家的模型，收敛速度比 Switch 的 Top-1 与 GShard 的 Top-2 快 2 倍以上。

但 Expert Choice 有一个绕不开的缺陷：它破坏了因果性。

专家在选择 token 时，需要看到整个批次的所有 token——包括序列中靠后的 token。这在自回归语言建模里是不可接受的：模型在预测第 t 个 token 时，不应该看到第 t+1 个 token 的信息。Expert Choice 的 token 到专家分配依赖同批其他 token，相当于让模型「偷看」了未来。论文自己提出过一个缓解设想（把同一序列的 token 分到不同组、各组独立做专家选择），但停留在 future work，没有实现。

这个限制让 Expert Choice 很难直接进入现代自回归 LLM 的主赛道。DeepSeek-V3、Qwen3、Mixtral 都采用 Token Choice（token 选专家）范式；Expert Choice 更多活跃在 encoder-decoder（它自己的实验就在 T5 上做的）和非自回归场景，比如扩散 Transformer（EC-DIT，2024）。

---

## Loss-Free Balancing：DeepSeek-V3 的答案

2024 年 12 月，DeepSeek-V3 要解决的是一道两难题：既摆脱辅助损失对路由器梯度的干扰，又保证负载均衡。

答案是：用一个可动态调整的 bias（偏置项）来替代辅助损失。

机制是这样的：每个路由专家有一个 bias，加在匹配度分数上参与 Top-K 选择。训练时，每步结束统计各专家的负载——过载的专家 bias 减小，欠载的专家 bias 增大。关键设计在于：**bias 只影响「选谁」，不影响「权重多少」。** 最终输出时用的加权系数仍然来自原始的匹配度分数。

这相当于在挂号系统里不搞「行政命令」，而是动态调整每个科室的「挂号门槛」——忙的科室提高门槛，闲的科室降低门槛，最终自然达到均衡。而且这个调整不干预医生的诊断质量。

DeepSeek-V3 论文在一个 228.7B 总参数（激活 20.9B）的 MoE 消融模型上显示，aux-loss-free 在绝大多数 benchmark 上优于纯 auxiliary-loss 基线：HumanEval 上 46.3 vs 40.2，GSM8K 上 74.5 vs 70.7。但严格说，V3 并非绝对没有辅助损失——它还保留了一个权重 0.0001 的序列级平衡损失，防止单条序列内路由极端不均。bias 更新也依赖全局负载统计，更新步长要在训练后期逐渐衰减，这些工程细节都是这套「免费」均衡的隐性账单。

但 Qwen3 给出了不同的答案。

---

## Qwen3 的不同选择

2025 年 4 月，Qwen3 发布。它没有跟进 DeepSeek-V3 的 aux-loss-free 方案，而是用回了辅助损失——只不过做了一个关键改进。

Qwen 团队（Qiu 等，2025 年 1 月）发现，现有框架的辅助损失都在 micro-batch 级别计算，而微批次只包含极少数序列，实际退化为「序列级均衡」。这导致同一序列内的 token（比如同一段代码）被强制均匀分配到所有专家，**抑制了专家的专业化**。

他们的解决方案是 global-batch load balancing loss：跨所有并行组同步统计后再计算损失。通信量只有 N 维向量（N 是专家数），延迟开销不到 3%（合适配置下），却换来了预训练困惑度约 0.1 的改善和 benchmark 分数约 2 分的提升。

Qwen3 还做了一个更激进的决定：砍掉了共享专家（shared expert）。DeepSeek-V3 每层有 1 个无条件激活的共享专家，Qwen3 明确把它去掉了——至少在共享专家这一点上与 DeepSeekMoE 的设计分道扬镳（细粒度专家分割仍然沿用）。

两条路线的分歧说明一件事：**MoE 路由的「最优解」尚未收敛。** 均衡与专业化的张力仍然存在，不同团队选择了不同的平衡点。

---

## 被丢弃的 token 去了哪里

均衡之争仍在继续，但在此之前还有一个细节：当专家容量不够时，溢出的 token 会被直接丢弃，跳过该层的 FFN（前馈网络）计算，经残差连接直通下一层。

这听起来很暴力，但 ST-MoE 的微调实验显示，丢弃 10-15% 的 token 对模型质量没有实质影响，甚至可能起到正则化作用。

Switch Transformer 在附录 B 的 No-Token-Left-Behind 实验中，尝试把溢出的 token 迭代重路由到次优专家，但没有发现实证收益。论文自己的推测是：网络已经学会了 token 与专家之间的关联，强行拆散这种关联（比如把 token 改派给次优专家）反而可能损害性能。

---

## 写在最后

回看 MoE 路由从 2017 到 2025 年的演进，一个反复出现的模式是：几乎每次有人提出一个「完美」方案，都会有一个隐藏代价让它无法成为通用解。

辅助损失引入了与主目标的梯度冲突。Expert Choice 破坏了因果性。Aux-loss-free 在 DeepSeek-V3 的大规模训练中验证了有效性，但 Qwen3 用实践表明它不是唯一答案。

这很像分布式系统里的 CAP 定理——均衡、专业化、因果性构成一个不可能三角，实际方案往往只能稳稳握住其中两个：

- 辅助损失：保住因果性和软性均衡，牺牲的恰恰是专业化——它逼着路由器把一些 token 派给不那么合适的专家
- Expert Choice：均衡是硬保障，专业化足够彻底，牺牲的是因果性——专家挑 token 要看完整批数据
- DeepSeek-V3 的 aux-loss-free：离三个顶点最近，但代价没有消失，只是挪到了三角之外——全局负载统计、bias 调度和一个兜底的辅助损失，一个都省不掉

三角没有免费的解，但取舍的位置并非一成不变。2026 年的 Expert Threshold Routing 论文把三者同时列为目标：每个专家维护自己的分数阈值，token 独立判定，路由既因果、又不需要辅助损失、计算还能按 token 重要性分配。不过它的实验止步于 2.4B 参数，这张答卷目前还远未到交卷时刻。

「MoE 路由」这个词背后不只是一个技术组件，而是一场关于「如何在约束条件下做最优分配」的持续探索。这个问题的终极答案，就目前的证据看，可能和分布式系统一样——没有银弹，只有权衡。
