# Jev 的核心本质：砍掉 Decode 的 Transformer

> **导读**：2026 年 9 月 15 日，一个拒绝生成文字的模型在硅谷刷屏。Jev 把大模型劈成两半，留下理解、砍掉生成，官方在其内部评测中称最高比前沿模型快约 194 倍、便宜约 445 倍，而且"不会幻觉"。随后几天，开源的复现版本接连出现，给出的评价相当冷静：它也就是一个大模型，只是用了一半。

2026 年 9 月 15 日，TypeSafe AI 发布了 Jev 的早期访问版本。据 Vercel 博客，上线其 AI Gateway 24 小时后，约 13% 的付费团队接入；据 36氪报道，发布视频播放量突破 3800 万次。发布它的人叫 Diogo Almeida，在 OpenAI 待过约四年，参与过 InstructGPT、ChatGPT 和 GPT-4；InstructGPT 那篇论文，正是把 RLHF（基于人类反馈的强化学习）推成大模型对齐主流方法的关键工作。

这个不写诗、不聊天、连一句完整废话都不生成的模型，热度来自它所放弃的东西。

## agent 循环里最贵的，是那些不需要说人话的决策

过去两年 agent 工程的现实是：一个循环里跑着大量小判断。

- 要不要再检索一次
- 这个工具该不该调用
- 结果够不够
- 该继续还是该停
- 这条指令有没有越界

这些判断大多只需要在几个选项里挑一个，或者回答一个是非。

它们现在大多由同一个大模型回答。而大模型回答任何问题，都要先把思考过程翻译成人话，token 一个一个往外吐。单个调用看着不贵，放进每秒十次的循环里跑一天，成本和延迟就一起复利。

如果这些小判断根本不需要被读给人看，那么让模型把它们说出来，本身就是一笔多余的开销。

## 保留 Prefill，砍掉 Decode

理解 Jev，先要理解自回归大模型的两次计算。第一次叫 Prefill，处理输入，把文字、图片编码进神经网络的隐状态（Hidden States）。第二次叫 Decode，一个一个往外吐 token，这一步的产物是给人类读的语言。

APUS AI 首席科学家张旭在复现 Jev 后给了一个非常直白的描述：

> Jev 的核心本质，就是它砍掉了第二步（Decode），只保留了第一步。它不再为了迎合人类而去逐字生成文本，而是直接在模型理解完信息的隐空间（Latent Space）里计算出结果。

官方把它包装成"System One Model"（系统一模型），名字取自卡尼曼《思考，快与慢》里那套快速直觉与慢速推理的划分。Jev 的输入是 state（状态，一段文本、一个 JSON 对象或一组文本），加上若干 typed question；一次并行前向，返回类型化的值，不是字符串。

它只认三种原语：

1. `choice`，从预定义选项里选一个，对应程序里的 switch；
2. `score`，在有序等级上打分，对应排序或阈值；
3. `noul`，回答一个是非问题，返回 0 到 1 之间的概率，对应 if。

一次典型调用长这样：

```Python
# Jev 风格的一次调用：state + typed questions，返回概率而不是文本
state = {
    "ticket_id": "TCK-8821",
    "body": "生产环境 API 从早上 6 点开始报错，要求立刻 SLA 赔付",
}
questions = {
    "queue": {
        "type": "choice",
        "instructions": "该工单归哪个工程队列？",
        "criteria": {
            "infra": "服务中断、网络、数据库故障",
            "billing": "退款、SLA 抵扣、账单争议",
            "support": "一般咨询",
        },
    },
    "churn": {
        "type": "noul",
        "instructions": "用户是否表达取消或流失意向？",
    },
}
# 单次并行前向，返回 queue=infra(0.96)、churn=0.914
```

快的原因大致有三层：

1. 跳过自回归解码，一次前向直接出结果；
2. 候选范围从十几万词表收敛到几个或几十个选项，张旭把它概括为对整个过程的"极度收敛"；
3. 选项之间没有先后依赖，可以并行判断，而自回归生成里每个 token 都得等前一个。

**这三点合起来，是把生成这条产线从推理路径里摘掉了。** 省下来的不只是时间，还有最贵的那部分算力。

## "零幻觉"被误读成了"不会错"

官方宣传里最容易被放大的四个字是"不会幻觉"，甚至是"零幻觉"。这个说法有一半成立，但成立的那一半跟多数人理解的不是一回事。

因为输出空间在请求时就已经定死，模型不可能返回 schema 之外的值。你给它 A、B、C，它编不出一个 D。用张旭的话说，"不出现幻觉和不出错是两回事"。TypeSafe 自己的技术说明里也承认，不出类型错误不是实证结果，而是因为 schema 匹配在数学上被保证了。

概率本身是否可信，则涉及 RLCD（Reinforcement Learning for Calibrated Decisions，面向校准决策的强化学习）。TypeSafe 把它定位成 RLHF、RLVR（基于可验证奖励的强化学习）之后的第三条线：RLHF 优化人类偏好，RLVR 优化可验证奖励，RLCD 优化的是概率与真实结果的吻合度。这里的关键词是"校准"（calibration），而校准是一句批量统计的话：在所有置信度为 0.8 的预测里，大约八成应该是对的。它不保证任何一条单独判断正确。

对这件事的独立检验，结果比宣传冷静得多。第三方机构 TrueStandard 用 108 条声明对比了 Jev、Gemini 3.1 Flash Lite 与 Claude Haiku 4.5，三者的校准误差（ECE，Expected Calibration Error）分别是 0.066、0.061、0.067，差距不到百分之一，几乎分不出高下；原始准确率上 Jev 也只领先 1.9 和 2.8 个百分点，优势集中在最难的第四档判断上（对 Gemini 3.1 Flash Lite 领先 8.4 个百分点）。换句话说，Jev 赢的是难题上的判断质量，不是概率的校准质量。

所以"零幻觉"只是一句工程保证，只覆盖输出不会越出 schema；准不准是另一件事，得单独验证。

开源这边的证据更直接。ConvAI Innovations 的 Laya 用严格 proper 的评分规则做奖励，理论上只有在报告真实概率时收益才最大。但作者自己在模型卡里写得很清楚：出厂权重是过自信的，要按问题类型和选项数量拟合温度，才能把校准误差从 0.466 降到 0.081。

## 落差：官方说是新物种，复现者说是半个模型

两边给出的解释开始分叉。

官方给 Jev 的定位是"机器原生、系统一、大型、可编程模型"，卖点是新架构、硬件感知的并行采样器、以及 RLCD 这个新训练范式。Almeida 在访谈里说，他不想把 AI 做成更像人的聊天对象，而是软件可以直接调用的智能基础设施，"智能更像数据库，而不是同事"。

复现者的评价要朴素得多。2026 年 9 月，APUS（麒麟合盛）AI 实验室发布了全球最早一批针对 Jev 的独立开源复现，封装为 Agent Skill `fast-browser-use`，MIT 协议。他们没有拿到权重和架构，只靠公开资料和输入输出反推工作流，基于 Qwen3.5 等开源模型还原了核心机制。张旭的结论是：拿出来的这部分"就是这个研究领域里的一个特例，没有什么特别神秘的地方"，9B 参数基本是可用门槛，五六亿的模型"很傻"。但他也留了余地，"更客观地说，它背后还有没有别的东西我不知道"。

另一路人马是 ConvAI 的 Laya。作者 Nandakishor M 主张自己一年多前就做过同一方向（arXiv:2503.23303），把 Jev 说成是对既有思路的重新包装，这一优先权主张在 Hacker News 上有争议。Laya 用 ModernBERT-large（约 4.2 亿参数）做基座，Apache 2.0 开源，在自家评测里给出 0.766，并拿 Jev 官方公布的 1.13.0 版本 0.727 来对比。

这个对比要打个折扣。Laya 的 0.766 是在 benchmark 训练集上微调之后的结果，零样本基座只有 0.362（随机基线 0.318）；Jev 那一栏则是官方公布的数字，按其零样本通用的定位属于零样本，并非 Laya 同场实测。拿微调过的模型和零样本数字比，基线并不对等。

把这几方并排看，落差主要不在技术，在别的地方：把隐空间决策这个研究了多年的方向，做成一个通用、零样本、schema 运行时定义的 API 原语，并且选在开发者被大模型账单压得最难受的那个时间点发布。复现很快，恰恰说明门槛不高，而 Jev 值钱的是产品化那一层。

还有一层：TypeSafe 至今没有公开 Jev 的架构、权重和训练方法，RLCD 的奖励函数也无从复现。外部观察者因此怀疑它建立在某个开源权重模型之上，而"新架构"这个说法目前无法从外部验证。

## 边界：它能接的活，和它接不了的活

把 Jev 当成"更快的万能模型"，往往会失望。它的能力边界相当清楚。

**最佳实践**大致是这么几条：

1. 把任务拆到最小的语义单元，让每个问题都容易被单独评估，而不是把所有要求塞进一个系统提示里；
2. 用概率当闸门而不是当答案，高置信度区间直接执行对应动作，中间地带回退到大模型或人工；
3. 涉及复杂推理、算术、计数、长文档、日期处理的任务，不要交给它；
4. 把它当可以写进单元测试的软件组件，为每条失败用例存一个测试，模型更新后重跑。

第 2 条大致是这样：

```Python
# 用 noul 的概率做闸门：高置信度直接处置，中间地带回退到慢模型
decision = jev.predict(state, questions)
p = decision["answers"]["churn"]["noul"]

if p >= 0.85:
    escalate_to_human(decision)      # 高置信度流失，升级人工
elif p <= 0.15:
    auto_close(decision)             # 明确不会流失，自动关单
else:
    handoff_to_llm(state)            # 概率落在中间，交给大模型
```

**常见误区**有三个：

1. 把它理解成"小号 LLM"。它不是参数更少的聊天模型，而是砍掉了 Decode 的半个模型，缺的那部分能力，很难靠放大参数补回来；
2. 把 `confidence` 当成"答对的概率"。它是把概率分布的形状压成一个数：某个选项越集中，confidence 越高；分布越散，confidence 越低。它衡量的是分布的形状，不是答对的概率；
3. 用它去做需要多步推理的活。推理链越长，对直觉的依赖越重，复杂任务上的准确率会明显下降。

## 快慢分工，不是谁替代谁

Jev 火起来的时候，很多人第一反应是生成式大模型要被颠覆了。这个判断可能过快了。

它擅长的是高频、原子化、环境交互一类的动作，不擅长长链条的规划与推演。张旭那个比喻说得挺准：模型是发动机，harness 是汽车的控制系统，agent 是整辆车；发动机变强，不等于轮子和方向盘不要了。更可能的形态是快慢分工，慢模型做规划和逻辑推演，快模型在需要即时反应的环节执行动作。

真正被改变的东西，或许是理解与生成这两件事终于可以拆开计费了。过去它们被绑在同一个自回归过程里，谁也离不开谁；现在有人证明，把生成那一半拿掉，剩下的一半依然能干活，而且便宜到可以在循环里被调用无数次。

这件事的意义，可能不在于某个模型是否配得上新物种四个字，而在于它让一整套被大模型成本挡住的用法，第一次以零样本、可编程 API 的形式变得划算。
