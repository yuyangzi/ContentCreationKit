# 模型蒸馏：为什么没有唯一正确答案

> **导读**：模型蒸馏被很多人理解为"用大模型的输出训练小模型"，但这个理解恰好错过了它最有趣的部分。从 Hinton 2015 年发现"错误答案的信息量大于正确答案"开始，蒸馏这个领域就一直在挑战直觉——教师不是越大越好，自蒸馏可以让学生反超教师，到了 LLM 时代甚至连"谁在教谁"都在被重新定义。蒸馏没有唯一正确答案，本文把它的内在矛盾摊开来看。

2015 年，Hinton 团队发了一个实验结果：在蒸馏用的转移集（transfer set）里把所有数字 3 的样本删干净，蒸馏出来的模型在测试集上对 3 的识别准确率仍然达到 98.6%（原文把 3 类偏置上调 3.5 后得到）。一个从没见过 3 的学生，照样学会了认 3。

关键在教师的 soft label 里。当教师看到一张像 3 又像 8 的模糊图片时，它输出的不是非黑即白的判断，而是一个概率分布，比如："38% 是 3，42% 是 8，11% 是 5……"。这张图片到底长什么样、它和哪些数字"长得像"——这些信息被编码在那些看似错误的概率里。

Hinton 管这叫 dark knowledge（暗知识）。

---

## 为什么错误答案的信息量更大

要理解暗知识，先想一个简单的分类问题：识别猫、狗、车。给一张金毛的照片，hard label 只说"这是狗"，但 soft label 会告诉学生："90% 是狗，7% 是猫，3% 是车"。那个 7% 的比例很有意义——它编码了教师对"猫和狗在某些角度下容易混淆"的理解。这些相对概率就是泛化结构本身。

问题是，当概率接近 0 的时候，标准交叉熵损失几乎不产生梯度，学生根本学不到。所以 Hinton 引入了一个现在家喻户晓的超参数：温度 T。

带温度的 softmax 公式很简单：

```
q_i = exp(z_i / T) / Σ_j exp(z_j / T)
```

T=1 是标准 softmax。T 越大，分布越"平"——那些原本接近 0 的小概率被放大，暗知识进入可学习的区间。当 T→∞ 时，蒸馏退化为直接匹配 logits（Caruana 2006 年 Model Compression 方法的特例，Hinton 论文证明了这一点）。

损失函数则是 hard label 和 soft target 的加权组合：

```
L = α · CE(y, p_s) + (1-α) · T² · KL(p_t ‖ p_s)
```

有一个细节很多人不注意：soft target 那一项必须乘 T²。原因是蒸馏梯度的量级大约是 1/T²，不乘的话，你一调温度，hard 和 soft 两项的相对权重就漂了。Hinton 原文里明确写了这个要求。

---

## 教师不是越大越好

如果蒸馏就是"让小学生做老师的题"，那直觉上教师越强，学生应该也越强。但现实比这复杂得多。

Hinton 的 MNIST 实验里有一个反直觉发现：当学生极小（每层 30 个单元）时，中等温度 T=2.5~4 显著优于更高或更低的温度。

机制在于学生容量太小、装不下教师的全部知识：温度越高，那些原本接近 0 的概率被摊开，学生被迫去匹配绝对值很大的负 logits，而它们很可能只是噪声；中等温度下这些 logits 的梯度权重自然变小，相当于被忽略（这是 Hinton 原文给出的推测性解释）。

这背后的本质是师生之间的容量差距，而容量差距带来的麻烦，远不止温度选择这一个。

这个"容量鸿沟"问题在深度学习时代被反复验证。Cho & Hariharan 2019 年的研究指出，教师和学生能力差距过大时蒸馏收益骤降。

到了 LLM 时代，ACL 2025 年的一篇论文（"Towards the Law of Capacity Gap in Distilling Language Models"）甚至给出了量化定律：最优教师规模与学生规模近似线性，系数约 2.5。

照此定律外推，7B 学生的最优教师大约在 17B-20B 量级，直接拿 70B 来蒸馏未必更好（该定律由 3B 以下小模型蒸馏归纳得出，7B 教师→3B 学生是论文验证的最大尺度，更大的学生规模属于外推）。

沿着这个逻辑再往前一步：如果教师太大不好，那师生一样大呢？Born Again Networks（Furlanello 等，2018）给出了更激进的答案——师生参数完全同构、不压缩，学生反而显著超越教师。CIFAR-10 错误率 3.5%，CIFAR-100 15.5%。

这和容量鸿沟是两个机制：前者的痛点是"装不下"，后者说明 soft target 本身就是正则化器，哪怕不做任何压缩也能从中受益。蒸馏的价值不只是"压缩大模型"。

## 蒸馏什么，怎么蒸馏

选完教师规模，下一步是选蒸馏方法。按"蒸馏什么"来分，有三条路线：

- **Response-based**：蒸馏教师最终输出的 logits 或 softmax 分布，Hinton 2015 原版就属于这一类。优点是简单直接，缺点是需要访问教师内部输出。
- **Feature-based**：蒸馏中间层表示。FitNets（2014）首次证明学生可以比教师更深更薄，10 倍少参数仍能反超教师。Attention Transfer（2016）让学生模仿教师的注意力图——不是学"答案是什么"，而是学"教师在看哪里"。
- **Relation-based**：不模仿单样本输出，而是转移样本间的关系。RKD（Park 等，2019）同时约束距离和角度：教师空间里 A 和 B 离得近，学生空间里也得近；教师空间里 ABC 构成的角度，学生也得保持。

这三条路线各有各的拥护者，但没有哪一条在所有任务上都赢。选哪条路线高度依赖任务——这本身就是一条核心规律。

---

## LLM 时代，蒸馏在教谁

到了大语言模型时代，蒸馏面临一个根本性的困难：LLM 输出的不是单个分布，而是几千个 token 序列。传统的 teacher-forcing 训练（学生看教师的 token 序列学习）存在分布失配——训练时学生看到的是教师生成的上下文，推理时它得自己一个 token 一个 token 地生成，误差一路累积。

**从 off-policy 到 on-policy**

MiniLLM（清华与微软研究院合作，ICLR 2024）和 GKD（Google DeepMind，2023）给出了同一个方向的解法：让学生自己生成序列，然后让教师对学生的输出打分。这就是 on-policy 蒸馏——学生不再模仿教师的轨迹，而是在自己的轨迹上接受教师的反馈。

这个转变的意义不只是工程优化。GKD 论文把蒸馏损失写进带 KL 约束的 RL 目标，指出 on-policy 蒸馏可以和 RLHF 无缝结合。蒸馏和强化学习的边界在这里模糊了（严格说，GKD 本身不对采样过程反传梯度，更接近监督训练，但目标函数已经和 RL 同构）。

MiniLLM 还做了一个关键选择：用反向 KL（reverse KL）替代前向 KL。前向 KL 是 mean-seeking，学生试图覆盖教师分布的所有区域；反向 KL 是 mode-seeking，学生聚焦教师最自信的模式。在生成任务上，反向 KL 更适合——教师分布的长尾部分通常是噪声，学生不该去学那些。

但这个结论也不是绝对的。2026 年 arXiv:2606.00306 的研究指出，在高温下前向 KL 反超反向 KL。MSE、KL、CE 的优劣也因任务而异：IJCAI 2021 说直接匹配 logits 的 MSE 在图像分类上优于 KL，大规模 NLP 实证研究（arXiv:2401.06356）说 CE 在 NLP 上优于 MSE。两种说法都对，因为任务域不同。

## 自蒸馏的悖论

自蒸馏（师生同构）在经典网络上已经证明了可以超越教师。但到了 LLM 场景，结论开始松动。

2026 年微软研究院与 KAIST 等机构的联合研究（arXiv:2603.24472）发现，LLM 自蒸馏会压制模型的认知不确定性表达（epistemic verbalization）。简而言之，模型学会了"自信地回答"，但不再会说"我不确定"。这在窄域内能快速涨分，代价是分布外（OOD）泛化受损——论文在多个模型上观察到最高达 40% 的性能降幅。

这个发现给自蒸馏画了一条分界线：目前来看，窄域任务（论文中有据可查的是化学、数学）可以用，宽域开放任务慎用。

---

## 蒸馏是个好搭档

蒸馏不是一个孤立的技术，它和量化、LoRA、CoT 都能组合。

**蒸馏 + 量化**：先蒸馏后量化，比直接量化的精度损失小得多。EdgeRazor（2026）用混合精度量化感知蒸馏，把 1.58-bit Qwen3-0.6B 的存储从 1.11GB 压缩到 0.19GB，解码加速 15 倍。

**蒸馏 + LoRA**：KD-LoRA（2024）在 GLUE 基准上保留 LoRA 98% 性能的同时模型紧凑 40%，GPU 内存省 30%。

**CoT 蒸馏**：DeepSeek R1 用 800K 条 SFT 数据（其中约 60 万条推理样本来自 rejection sampling）蒸馏到 Qwen/Llama 系列，R1-Distill-Qwen-32B 在 AIME 2024 达到 72.6%（出自 DeepSeek-R1 官方技术报告），超过 o1-mini 官方公布的 70.0%。

- 但 CoT 蒸馏有一个精细的问题：小模型对推理链粒度的需求不是单调的。2025 年 arXiv:2502.18001 发现，强模型受益于细粒度推理链，弱模型反而适合更简单的 CoT。

---

## 没有唯一正确答案

蒸馏的本质，在这十几年里被反复重新定义。

- 2015 年 Hinton 说它是"从 soft target 中提取暗知识"
- 2018 年 Born Again Networks 说它是"一种正则化"
- 2023 年 GKD 说它是"带 KL 约束的 RL"
- 2026 年的 On-Policy 蒸馏综述（arXiv:2604.00626）说它在 LLM 场景下已经变成了一种"交互式模仿学习"

这些描述并不矛盾，它们各自捕捉了蒸馏在不同阶段、不同任务下的一个侧面。蒸馏这个领域最核心的特征，可能就是**不存在一个在所有场景下都最优的通用答案**：

- MSE、KL、CE 这几种损失谁更好，取决于任务域（图像还是 NLP）
- 教师规模有最优区间
- 自蒸馏在窄域有效但在宽域有害
- 前向 KL 与反向 KL 的优劣取决于温度（低温反向占优、高温前向反超）

这种"视场景而定"的特质不是蒸馏的缺陷，而是它的真实面貌。理解这一点，可能比记住任何一个具体的蒸馏公式都更有用。
