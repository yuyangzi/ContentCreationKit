# 统一多模态的不同路线：一个主干，几种目标

过去两三年，理解和生成能否放进同一个模型，答案一直在变。

在大语言模型出现之前，图像理解和图像生成是两条泾渭分明的技术线。理解一侧，视觉语言模型（VLM）沿用自回归路线，把图像编码成特征后交给语言模型输出文字；生成一侧，扩散模型（Diffusion Model，通过逐步去噪生成图像的模型）占据主导。两边的差异体现在三个层面：

- 架构
- 训练目标
- 数据格式

于是产品上常见的做法是把两个模型拼在一起。

统一多模态要解决的，就是让同一个模型既能看懂图像、音视频，又能生成它们。学界对"统一"的定义并不一致。按架构主干是否共享、训练目标是否共存划分，现有路线大致可以分为四类。

## 纯自回归：所有模态都是 token

最直接的做法是把图像也切成离散 token（由 tokenizer 学到的一套码本），再和文本拼成一条序列，用同一个 next-token 预测目标训练。

Chameleon（arXiv:2405.09818）是这条路线的代表，综述文献也把它列为纯自回归统一的典型（arXiv:2505.02567）。Emu3（arXiv:2409.18869）把这一思路推进到图像、视频和文本的统一生成，论文题目"Next-Token Prediction is All You Need"即是这一主张。GPT-4o 是闭源模型，官方定性为自回归原生生图（OpenAI System Card 附录，2025-03-25），架构未公开，无法归入四类，但可作为纯自回归路线的闭源注脚。

这条路线的好处是结构最简单，和大语言模型的训练与推理基础设施完全一致。难点在 tokenizer：图像被压成离散码，信息损失往往难以避免，生成质量会受限于码本的表达力。

## 解耦视觉编码：理解与生成各看一套特征

Janus（arXiv:2410.13848）观察到，理解需要语义级特征，生成需要像素级细节，两者对粒度的要求不同。它的做法是为理解和生成各配一个视觉编码器，但仍然共享同一个自回归主干。

这个设计说明了判定标准的一个要点：输入表示可以不同，只要主干共享，就算统一。Janus 的主干是共享的，因此它属于统一路线，尽管视觉输入端是分开的。代价是两套 tokenizer 把表示空间一分为二，这也是 UniAR 这类工作批评它的出发点。

## AR 加扩散：文本用 next-token，图像用去噪

Transfusion（arXiv:2408.11039）把两种目标直接加在同一个 Transformer 上：文本 token 使用语言建模损失，图像使用扩散损失。训练时，文本部分保持因果注意力，每张图像内部则是双向注意力。

训练目标可以写成如下示意形式：

```python
# Transfusion 风格的混合训练（示意，省略细节）
loss_text  = cross_entropy(model(text_tokens), next_text_tokens)
loss_image = diffusion_mse(model(noisy_image_latents, t), noise)
loss = loss_text + lambda_img * loss_image
```

BAGEL（arXiv:2505.14683）采用类似的双分支思路：理解侧用 SigLIP2 这类语义编码器，生成侧用 VAE 的重建 latent，两者在一个 Transformer 里交互。

这条路线的代价是训练更复杂。两种目标的权重需要调校，两侧的梯度也会相互影响。

## 离散扩散：文本和图像都用掩码去噪

Show-o（arXiv:2408.12528）在一个 Transformer 里同时做自回归和离散扩散，文本用自回归，图像 token 用离散扩散。UniDisc（arXiv:2503.20853）是较早的统一离散扩散工作。Omni-Diffusion（arXiv:2603.06577）是 2026 年 3 月的工作，以掩码离散扩散作为统一主干。

这条路线的目标是并行解码，理论上比逐 token 生成更快。但在长文本推理上能否与自回归持平，目前的证据还不多。

## 音频与视频：证据较少的一段

Emu3 已把视频纳入自回归，本节讨论的是含音频的全模态。把视频和音频纳入统一，目前主要依靠全模态模型的工程整合。Qwen2.5-Omni（arXiv:2503.20215）采用 Thinker-Talker 结构：Thinker 负责理解和文本生成，Talker 以自回归方式预测离散语音 token，再交给解码器输出波形。Qwen3-Omni（arXiv:2509.17765）同样采用 Thinker-Talker 结构，并引入 MoE，报告称在文本、图像、音频和视频上没有因统一而降质。这一结论来自作者自报的基准结果，尚未有独立复现，读者需要带着这个前提看待。

## 2026 年的新问题：统一的代价

2026 年的几项研究对"统一是否真的带来协同"给出了更直接的实验证据。

一个常见假设是，理解和生成的训练会相互促进。2026 年的几项研究对此提出了质疑。arXiv:2609.01607 指出，功能上的统一并不保证学习上的协同：两个目标可能相互增强，也可能争抢模型容量，或只是并存。arXiv:2608.17564 归纳指出，在受控消融中加入生成目标后，理解能力反复表现为持平。关于"梯度冲突能否预测两者的权衡"，arXiv:2609.38465 的审计工作表明，这一前提此前并未被直接检验。

目前的结论是，协同需要靠具体设计争取，不能默认发生。

## 工程上的几条经验

1. 视觉 tokenizer 的选择决定了统一的上限。UniAR（arXiv:2606.18249，ICML 2026 poster）主张用一个离散 tokenizer 同时服务理解与生成，让两者共享同一套上下文。这一思路与 Janus 的解耦方案形成对照，哪种更好还需要更多对比数据。
2. 联合训练前先做单任务消融。协同效应不能凭直觉假设。如果理解与生成之间没有可测的协同，联合训练只会增加成本。
3. 不要把梯度冲突指标直接当作优化目标。arXiv:2609.38465 的审计说明，这个指标与权衡之间的关系尚未得到确认。
4. 服务端要按阶段拆分（部署侧）。Qwen3-Omni 采用 Thinker、Talker、Code2Wav 的流式流水线，首包延迟和整体延迟的优化方向不同。vLLM-Omni（arXiv:2602.02204）讨论了这类任意到任意模型的分离式部署。

## 三个常见误解

**误解一：统一等于每项都强。** Qwen3-Omni 的报告显示统一没有明显降质，但这是作者自报，而且其他路线的消融研究常显示收益不明确，甚至在受控设置下长期持平。统一模型通常是在某一侧做了取舍，取舍在哪里，要看具体的基准。

**误解二：统一必须是同一个表示空间。** Janus 和 BAGEL 都使用了分开的视觉编码器，它们仍然属于统一路线。表示是否统一是一个设计选择，主干是否共享才决定模型是不是统一的。

**误解三：离散或连续的高下能从路线名字看出来。** 纯自回归路线用离散 token，AR 加扩散路线用连续 latent，离散扩散路线也用离散 token，但不用逐 token 的自回归顺序，而是掩码并行去噪。哪一种更强，取决于 tokenizer 质量与训练配方，路线名字本身给不出答案。

## 结语

统一多模态的路线分歧，表面上是架构选择，背后是对"理解与生成是否共享同一种表示"的不同判断。纯自回归的假设是肯定的，解耦视觉编码承认表示可以分开，AR 加扩散则承认两者需要不同的目标。2026 年的实验让人更谨慎：统一不是免费的，协同需要被验证。
