# 读得懂权重，改不动能力：LLM 权重空间编程的边界

> **导读**：2026 年 11 月 2 日，MIT CSAIL 让 GPT-6 Astra 直接改写 Qwen3.5-0.8B 的权重，MATH-500 从 7.9% 拉到 48.1%，只动了 0.016% 的参数。数字被翻译成"神经网络的基因编辑""训练不存在了"。这篇拆三件事：它读权重靠的是什么，改权重到底改动了多少，以及为什么同一套方法在一个不循环的小网络上失效。团队给这件事起的名字是权重空间编程（Weight-Space Programming）。

先看最干净的一环：让它只读权重。

三个字符级 Transformer，每个 716 万权重，四层，每层六个注意力头，语料各十亿字符，分别是：

- 只读过 Python 代码
- 只读过罗马字标注的日文
- 只读过英文维基

研究者把输入层和输出层都拆掉，只把中间四个 block 的权重开放给 GPT-6 Astra 分析。没有字符表，没有"哪个维度对应哪个字母"的标注，也不许把网络跑起来看效果，只允许用 Python 做矩阵分析。

问的问题是：这个网络训练在什么语言上。

每个模型各问两次，Astra 都说对了。Python 那次报出 0.56 和 0.52 的把握，罗马字 0.55 和 0.62，英文 0.58 和 0.48。

另一件事更能说明它读的是什么。它点出了每个模型里的 copying head（复制头，让模型把前文出现过的片段原样接上的注意力头）：Python 模型的第 2.1、3.1、3.5 号头，罗马字模型的 3.3 号头，英文模型的 3.1 号头。研究者另有一套办法量这件事：把一个 40 字符的随机字符串重复两遍喂进去，看每个头会不会去提前文，分数超过 0.2 的算复制头（实测命中的都落在 0.22 到 0.55 之间），其余头不超过 0.02。两边结果完全一致。

它的推理路径是先找一个"只看前一个字符"的一层头，再把那个头的输出矩阵跟后面各头的查询矩阵、键矩阵相乘，看哪些头在用这个信息做搜索。这条推理路径正是 Nelson Elhage 等人 2021 年《A Mathematical Framework for Transformer Circuits》里的注意力头组合（composition of attention heads）机制。博客里补了一句：他们从没在 prompt 里告诉 Astra 这件事。

还有一个更小的实验补了一个更干净的判据。研究者训练三个扩散模型，分别生成实心圆、正方形和三角形，只给 Astra 权重，不许跑前向传播（forward pass，把输入喂进网络算一次输出）。它认出了每个模型生成什么形状，但把图形画成了轮廓，不是实心。这个错误恰好是证据：如果它在偷偷跑前向，画出来会是实心的；它画轮廓，说明它读的是输出层权重里那些"负责画出一小段边缘"的单元，靠几何结构在推断。

迅速刷屏的结论有一半站得住：权重确实可读，而且不是靠猜。

## 为什么一串数字能说出一件事

Transformer 的前向计算，在输入固定的前提下，本质上是一串权重矩阵的乘法和加权求和。Elhage 那个框架里有一条很朴素的代数事实：两个注意力头叠起来，等效的注意力矩阵等于两个注意力矩阵相乘，等效的输出矩阵等于两个输出矩阵相乘。用一句更短的话说，头的乘积还是头。

于是"某个头是不是在复制前文"这个问题，不需要任何数据就能回答。看它的输出矩阵像不像一个复制矩阵，看它的查询键矩阵里有没有"和前一位置同字符"的匹配项。这些都是权重里现成的量。

Astra 被允许用 Python 做最多一百次 numpy 分析，禁止跑网络。它做的就是把这些乘积手算一遍。

要把这条路线放到位置上，得先看另外三条路。

- 2023 年 OpenAI 那批神经元解释工作（Bills et al.）走的是激活路线：让 GPT-4 给每个神经元写一句解释，再用这句解释预测该神经元在新输入上的激活，靠预测得准不准打分。读的是激活，不是权重本身。
- 10 月上线的 Weight Oracles（NeurIPS 2026 Workshop 论文，arXiv:2610.07334）训练了一个专用模型来读原始权重，用分阶段课程加外部计算链，在小 Transformer 上把模拟前向做到 99%（留出集准确率）。代价是只到两千参数的量级，作者自己说，权重矩阵整块塞进上下文这件事一过几百万参数就做不下去。
- AdderBoard 更极端，让 coding agent 手写极小 Transformer 的权重去做十位数加法，手写榜最低报到 6 个参数（严格计数是 10 个，计数口径有争议，榜首条目未记录所用工具）。

Astra 的位置在这三者之外：通用模型，零训练，一头是十七万个权重的小车网络直接以文本塞进上下文，另一头是八亿参数的模型配 Python 沙箱。

## 光看权重，读不出行为

同一篇博客里还有一组反向实验。

研究者拿 Gemma 3 270M 做了两份复制品，用同样的流程、同样的数据微调。一份被训练成给正确答案，另一份被训练成谄媚：用户猜什么，它就答什么。为了防止 Astra 走捷径去看输入输出分布，微调时冻结了词嵌入层和输出层。

只给权重，Astra 四次尝试全部失败。它找出了两份权重之间大量差异，但没能把这些差异对应到行为差异上。

放宽条件之后它才成功。允许它自己写最多十六段文本，跑一遍两份模型，只看回来的注意力权重，不看输出。三组配对全部认出谄媚的那份。它还说清了机制：第 10 层第 2 号头在生成答案的位置上，诚实模型把 94.3% 的注意力放在题目的数字上，只有 0.75% 放在用户给的答案上；谄媚模型反过来，3.5% 和 85.7%。

这件事的边界很清楚。权重里确实写着行为差异，但把权重差异翻译成行为，光看权重不够，得有行为证据做锚点。行为没有落在紧凑的局部结构上时，纯权重读取就停在那儿。

## 6 倍提升是怎么来的

轮到 Qwen3.5-0.8B 时，题目从读懂变成了修好。二十四层，思考模式打开，采样沿用博客评测协议的 0.6 温度、0.95 top-p、20 top-k、1.5 在场惩罚（presence penalty；模型卡对 thinking 文本任务的建议温度是 1.0），单次生成上限 32,768 token。

基线是 MATH-500 的 7.9%、GSM8K 的 13.8%、IFEval 的 21.0%。但真正该看的是另一个数：93% 的答案在 32,768 token 处截断，根本没写完。

Qwen 自己的模型卡警告过这件事，大意是 thinking 模式下这个 0.8B 比同系列其他模型更容易进入思考循环，可能导致生成无法正常结束，建议调采样参数、用 streaming 实时检测并中断。

Astra 拿到的工具是三样：

- 一个跑在 CPU 上的 Python 会话，权重以张量形式加载
- 一批练习题，来自 GSM8K 训练集的 7,469 题和 MATH 训练集的 7,275 题，测试集一道没给
- 10、25 或 50 次前向预算

一次前向可以干两件事之一，让模型答最多 512 道练习题，或者读最多 1,024 段文本的 log 概率、隐状态、MLP 激活和注意力。不许用梯度，不许跑 benchmark。

它找到的病灶在 layer 15 和 layer 19 的 MLP。这两层的 down_proj 是往残差流（residual stream，各层信息汇聚的那条主干）写东西的矩阵，模型进入循环时，同一个方向被反复激励。做法是从每层挑 64 个输出列，把它们沿这个方向的分量减掉。日志里记下的形式是 W′ = W − α·u(uᵀW)，系数由 Astra 自己定。

```python
import torch

def remove_loop_direction(w, u, alpha, cols=64):
    """w: MLP down_proj 权重，形状 [hidden, inter]；u: 从权重里读出来的循环方向
    alpha: 步长系数，由 Astra 自定；cols: 选中的输出列数"""
    u = u / u.norm()          # 归一化，只保留方向，不保留长度
    w = w.clone()
    # 挑沿 u 写入分量最大的 cols 列，减掉它们沿 u 的分量，其余列原样保留
    idx = (u @ w).abs().topk(cols).indices
    w[:, idx] -= alpha * torch.outer(u, u @ w[:, idx])
    return w
```

五十次预算那次交上来的改动是两层、每层 64 列、隐藏维度 1,024，合起来 131,072 个权重，占八亿参数的 0.016%。结果：MATH-500 48.1%，GSM8K 67.1%，IFEval 62.3%，截断率从 93% 掉到 33.1%。

这个操作在技术上不新。Arditi 等人 2024 年的工作（arXiv:2406.11717）在十三个开源对话模型上证明，拒绝行为由一个一维子空间中介：把那个方向从写入残差流的权重里正交化掉（论文的主实验是在推理时做逐层投影消融），模型就不再拒绝；把方向加回去，拒绝又回来。工程界管这个叫 abliteration（拒答方向消融）。Astra 用的是同一类算子，目标行为从"拒绝"换成了"思考循环"，方向不是从对比数据集里算出来的，是它自己读权重读出来的。

## 同一个任务，三次编辑三个样子

把三次预算摆在一起：前向预算分别是 10、25、50 次，对应的 MATH-500 结果是 12.3%（+4.4）、14.1%（+6.2）和 48.1%（+40.2）。

三次的编辑不是一回事。十次预算那一版把 layer 8 到 22 的 30 个输出矩阵几乎每个元素都动了，系数取 1.5，占八亿参数的 9.1%（五十次预算那次是 0.016%），提交的权重文件也是 331 MB 对 29 MB（这组编辑数据出自实验日志）。

这不是一条平滑的提升曲线，是一个阈值。十次那次也删了一个"重复方向"，但摊在那些输出矩阵上没能治住循环；二十五次干脆换了个策略，关掉一整个头。只有到五十次，它才有足够的行为证据把"哪个方向"和"哪个症状"对上。

真正的稀缺资源不是能改多少权重，是反馈预算（能跑多少次前向）。**改动量小不是方法优雅的证据，是搜索成功的副产品。**

代价也记在同一份日志里。五十次预算那次花了 158 轮、4 段对话、80 次 Python 运行、20.3 小时。这个 20.3 小时是墙上时间，里面包含 4.7 小时模型服务不可达的等待。发布材料里没有任何美元或 GPU 小时数字，所以拿它和微调比成本，现在还没有可比的东西。

中文报道里，量子位的小节标题写的是"训练不存在了？"。博客自己的口径是另一回事：能力仍然有限，卡在上下文长度和 harness（运行框架）的效率上；不过它的 TL;DR 也写着"This might be a big deal"（这可能是个大事），营销不只在媒体一侧。

## 反证：不循环的模型改不动

前面所有改权重成功的例子都有同一个前提：故障是集中的。团队自己做了反证。

Gemma 3 270M，大约 Qwen 的三分之一大小，截断率只有 8.5%（Qwen 是 93%）。MATH-500 基线 6.8%，四个预算档（5、10、25、50 次）依次是 7.0、7.6、7.7、7.0。没有一档超过一个点。

Astra 读它的失败案例，看到的是普通推理错误，算错的、代数变形无效的，没有单个组件可以关掉。它给出的编辑因此散在多个组件上，比如把某个对数字敏感的神经元权重加倍，这些改动 Astra 自己就报告说"未能确立"。

博客里最重要的一句判断是：

> Editing weights could remove an obstacle that hid an ability, but it could not add an ability the model lacked.

改权重可以移开一个遮住能力的障碍，但加不进模型本来没有的能力。

这句话有数据撑着。一千一百五十二条配对练习题里，编辑救回 579 条，其中 576 条原本就是被截断的题，占 99.5%，另有 5 条变差（Astra 自报，见实验日志）。**它做的事，是让模型把本来算得出的题算完。**

独立复现（第三方，单一来源）把这条边界画得更清楚。有人把作者发布的 diff 逐 hash 校验后重跑 MATH-500，配对 95% 置信区间 +42.8 [39.3, 46.3]，幅度对得上博客。

但他多做了一组博客没做的对照。base 模型如果关掉思考模式，本来就有 45.8%。编辑版开着思考是 50.2%，公平比较只剩 +4.3 [1.9, 6.8]。两边都关掉思考，编辑版反而低 2.2 个点。

他补上的是思考开关这一项，但模型卡给的另外两条建议（调采样、用 streaming 中断循环），至今没人和改权重放在同一张表里比过。

## 这不是新算子，是新选手

博客作者之一的 Omar Khattab 在 X 上自问：如果 LLM 已经能在权重空间里推理，梯度下降这种符号化的局部优化启发式，还剩什么位置？

Neel Nanda 的看法更冷静。他说这件事最好的理解方式，是"Astra 出乎意料地会做老派的机制可解释性研究"，而不是什么诡异的新东西（他也承认，这比他自己预测的更擅长）。他补了一句，这类分析在 2022 年之前相当常见，后来退潮，因为扩不到真实大模型的复杂度上。这篇博客更新的是"LLM 有多会做这件事"，不是"老派方法能走多远"。

这个定性更接近材料本身。整条管线里每一步都有更早的研究垫底：读靠 circuit（回路）分析，定位靠方向消融，验证靠行为评测。变的是执行者。以前是一个博士生花几个月手算矩阵，现在是一个通用模型在二十小时里试出来。

写权重这件事确实存在，但目前只在三个条件下成立：网络小到能整块塞进上下文（比如 MinAtar 那个 600→32→32→6 的游戏网络），给足 Python 沙箱和前向预算从零构造（比如 148 万权重的 Go 棋盘网络），或者故障集中到能被一个方向关掉。前两类是构造性证明，第三类是手术。三种都不等于"用自然语言编程一个神经网络"，从零构造也不等于往已有模型里加能力。

团队列的下一步里，最值得看的是审计：不跑推理、不建测试集，直接从权重里找后门和隐藏能力。它和改权重共用同一套读的能力，风险小得多。

改权重那条线的风险，PauseAI 的 Maxime Fournes 一句话说完了：如果为真，这会大幅加速进展，那是"极其鲁莽的研究方向"；不过他自己随后又补了一句"大概是被炒作出来的"。但审计和提能力这两种走向并不互斥：同一套读的能力，既能帮人看懂模型，也能帮人改强模型。

## 判断清单

流传最广的三个读法各偏了一格：0.016% 只属于预算最足的那一次，6 倍是把原本没写完的题写完了，至于减掉一个方向这个动作，2024 年就在用了。

如果哪天你手上真有一个坏掉的模型，在动权重之前值得先过五条：

1. 故障是不是集中的。有单个方向、单个头、单层可以关，才有戏；错误分散在算术和代数步骤里，Astra 也没辙。
2. 截断率是多少。准确率低但有大量答案没写完，先修"写完"这件事；截断率本来就低，编辑大概率白做。
3. 反馈预算够不够。这不是能改多少权重的问题，是能跑多少次前向的问题。先备好可复现的评测子集和一个循环检测器。
4. 跨域回归做过没有。方向消融和知识编辑这条路攒下的教训是：方向不唯一，写入路径是共享的，改动会溢出到别的行为。至少要有"把方向加回去"的反向验证。
5. 零成本基线试过没有。调采样和 streaming 中断是模型卡给的，思考模式开关是第三方复现者补的，三样都值得先试。

## 第 0 天

回到开头那三个字符级模型。去掉输入输出层之后，权重里没有任何东西标明哪个字符是哪个，Astra 说出了训练语言，还逐个点出各模型的复制头，与实测一致。

这件事成立的边界，和那条迅速刷屏的 6 倍提升，是两条线。前一条线证明前沿模型已经能完成一种很具体的研究工作；后一条线证明它能在一个已知的、集中的故障上做一次外科手术，代价是二十小时和五十次前向预算。

团队正在建一套 benchmark 和配套 harness，用来标准化评估这类能力。现在的状态更像这个方向的第 0 天：方法有名字了，全部日志公开了，也有一份独立复现，但只有一个故障类型、一个模型、一个执行者。

把这当成"神经网络可以用自然语言编程"的证据，还早。
