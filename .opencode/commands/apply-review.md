# 执行修改建议

## 目标

将审核阶段输出的全部修改建议一次性落到文件上，重点清除三类内容：错误内容、模糊表述、无法验证的内容与数据。

## 前置条件

- 已产出修改建议清单（`/review-topics`、`/review-reference`、`/review-draft`、`/review-article` 之一）
- 用户已确认执行全部建议

## 输入

- 修改建议清单（对话中）
- 待修改文件：`content/topics/`、`content/reference/`、`content/draft/`、`content/article/` 之一
- `StyleRule.md`——编辑风格规则（完整版）

## 步骤

### 1. 汇总建议清单

- 收集当前主题下已确认的全部修改建议，逐条编号
- 标注每条建议对应的文件与具体位置
- 若存在建议冲突或表述不清，先向用户澄清，不自行取舍

### 2. 分三类处理内容

1. **错误内容**：日期、数字、来源归属、产品名、定价等事实错误——按核实结果直接改正
2. **模糊表述**：绝对断言、情绪标签、元叙述、设问修辞——按 `StyleRule.md` 改写为直接陈述
3. **无法验证的内容与数据**：无法找到 ≥2 个独立来源交叉验证的数据——**直接删除，不保留"待验证"标记**

### 3. 执行修改

- 逐条应用建议，改完一条勾掉一条
- 删除操作优于保留：宁可少一个数据点，不留存疑内容
- 只改建议涉及的句子和段落，不顺手重写无关部分

### 4. 复查一致性

- [ ] 前后数据口径一致（同一事实不在 A 处一个说法、B 处另一个说法）
- [ ] 删除后段落逻辑仍连贯，无悬空指代
- [ ] 无残留的"待验证""存疑""暂未确认"标记
- [ ] 修改后的表述符合 `StyleRule.md`

## 输出

- 已更新到原路径的文件（就地修改，不新建文件）
- 执行结果清单：每条建议的状态（已执行 / 已删除 / 已跳过及原因）

## 约束

**必须遵守：**

- 逐条执行，完成后汇报每条建议的去向
- 无法独立验证的内容与数据**一律删除**，不保留"待验证"标记
- 修改范围限定在建议涉及的句子与段落

**禁止操作：**

- 不要跳过任何一条已确认的建议
- 不要新增原文没有的数据或事实
- 不要仅凭模型训练数据判断真伪，须以搜索查证结果为准
- 不要修改建议未涉及的段落结构或排版
